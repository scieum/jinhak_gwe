# 수시 입결 정리 — 2026-11-25

기존 통합 원본 132,605행에서 `round=수시`인 **101,406행**을 분리했다. 196개 대학 기준 목록 중 수시 자료가 있는 **186개 대학**, 캠퍼스·원문 표시명 기준 **227개 자료 묶음**이다. 원본의 수치·빈칸·학년도·전형명·모집단위명·출처·주석을 모두 보존했으며 정시 등 나머지 31,199행은 원본에 그대로 있다. 신규 웹 수집이나 원문 전수 재검수 작업은 아니다.

| 학년도 | 수시 관측 행 |
|---|---:|
| 2024 | 33,469 |
| 2025 | 32,974 |

행 수는 서로 다른 출처·지표를 포함한 관측 건수다. 고유 전형 수, 학생 수 또는 전 전형 수집 완료를 뜻하지 않는다. 대학별 합계에는 본교·캠퍼스 자료가 함께 포함되며 캠퍼스 미표기 자료를 주소나 학과로 추정 배분하지 않았다.

## 지표와 확인 대상

- 50% 또는 70% 컷 기재: 49,754행. 평균·최저·80% 컷을 70% 컷으로 바꾸지 않았다.
- 기타 성적·통계·안내 원문: 45,823행. `cut_other`에 비공개 안내 등이 섞여 있으므로 전부 수치 성적이라고 부르지 않는다.
- 모집·지원·경쟁률·충원만 있는 행: 5,771행.
- 위 수치 칸이 모두 빈 행: 58행. 원문 주석을 유지했다.
- 정확히 동일한 20열 중복: 0행. 원본 삭제·임의 병합 없음.
- 우선 확인 대상: 3,027행. 같은 키의 값 차이 419묶음·1,149행, 컷 순서 770행, 전형 유형 공란 806행, HTTP 출처 242행, 명시적 합계 범위 70행. 사유는 겹칠 수 있다.

`same_key_different_values`는 오류 확정이 아니다. 학년도·모집시기·전형유형·전형명·모집단위·지표·산출대상·등급제가 같은 행을 비교한 후보이며, 주석에 있는 모집대상이나 정렬 방식 차이로 설명될 수도 있다. 값 차이를 평균 내거나 한쪽 값을 임의 채택하지 않는다. HTTP 출처도 HTTPS로 임의 치환하지 않았다.

`structured_cut_candidate` 48,760행은 이번 기계적 점검에서 별도 사유가 없는 컷 기재 행이라는 뜻이다. 공개 승인·정확성 보증·연도 간 비교 가능 판정이 아니다. 교과등급·환산점수·논술점수는 원문 지표대로 분리했다.

## 파일

- `susi.csv`: 기존 앱 관리자 CSV 가져오기와 같은 20열. 대학·캠퍼스·학년도·유형·전형·모집단위·지표·출처순으로 정렬했다.
- `row-index.csv`: 원본 레코드 번호, 원본 행 SHA-256, 현재 대학 ID, 캠퍼스, 분류, 검토 사유를 원문 20열과 함께 연결한다. 레코드 번호는 헤더를 1로 센 CSV 논리 행 번호다.
- `review-queue.csv`: 3,027개 우선 확인 행과 원문 URL·쪽수. 오류 확정 목록이 아니다.
- `same-key-candidates.csv`: 같은 비교 키의 관측값을 출처별로 대조하는 목록.
- `university-year-coverage.csv`: 기준 목록 196개 대학 × 3개년 = 588개 범위. 수시 행이 없으면 `no_collected_susi_rows`로 표시하며 미실시·비공개로 단정하지 않는다. 경찰대학 등 다른 모집시기 표기를 쓰는 학교도 수시 공백으로 나타날 수 있다.
- `program-index.csv`: 캠퍼스 원문 이름·학년도·전형별 모집단위 이름 수, 관측 행 수와 지표 목록. 같은 학과명의 연속성이나 모집인원 합계를 계산하지 않는다.
- `app-import/`: 기존 앱의 `parseCollectedIndex` / `parseCollectedRows`로 읽을 수 있는 수시 전용 사전 압축 묶음. 모든 파일은 draft이며 원본 해시를 가진다.
- `summary.json`: 원본 해시와 집계, 확인 사유, 자료가 없는 대학·연도 목록.

기존 앱의 전체 수집 자료 패키지는 수시·정시를 함께 제공하므로 덮어쓰지 않았다. 2026-11-25 후속 사용자 요청으로 수시 전용 정리본을 **실제 앱의 대학별 참고 조회 화면**에 연결했다. `app/public/data/susi-results/`에 행별 확인 항목을 포함한 별도 묶음을 생성하며 대학별로 필요한 파일만 읽는다. 검수 완료 입결(`released-results.json`)이나 계산용 자료를 새로 승인한 것은 아니다.

일반 실행에서는 개인 성적 샘플 모드와 관계없이 실제 수시 자료를 표시한다. 원문 대조 대상 3,027행은 표·원문 상세에 확인 사유와 원래 값을 남기고 그래프에서는 제외한다. 동일 학과·학년의 출처별 값을 보존하고, 점을 눌렀을 때 해당 출처로 연결한다. 같은 표에 여러 지표·산출 기준이 있으면 함께 표기한다. 대학별 화면의 ‘수시 원문 전체 보기’는 수시 전용 표로 연결되며, 기존 관심 전형의 수시·정시 원문 링크는 계속 동작한다.

## 재현·검증

저장소 루트에서 `python app/tools/organize_susi_results.py` 실행. 원본은 `_all.csv`, 대학 ID 연결 기준은 `work/_data/university-directory/directory.json`이다. 기존 원본·캠퍼스 명칭을 바꾼 경우 다시 실행한다. 생성기가 20열 전체 다중집합과 원본 파일 해시를 비교해 누락·값 변경이 없음을 확인한다.

검증: `python -X utf8 -m unittest discover -s app/tools -p test_organize_susi_results.py`, 앱 폴더에서 `npm.cmd run test -- tests/susi-organization.test.ts`.

앱 자료까지 갱신: 앱 폴더에서 `npm.cmd run data:build-susi` 실행. 원본과 정리본 해시가 다르면 내보내기를 중단한다. 실제 앱 파서·확인 항목 검증은 `tests/susi-results.test.ts`, UI 검증은 `tests/university-result-overview.test.tsx`에서 수행한다. 배포 자료 검사·번들에도 수시 패키지를 포함한다. 코드만 공개 방침에 따라 생성 JSON은 gitignore 대상이다.

G5 시안 대조에만 `VITE_SUSI_DESIGN_FIXTURE=true`를 설정한다. 일반 개발·배포 빌드에는 설정하지 않는다. 실제 데이터 브라우저 검증과 시안 예시 검증은 별도로 수행한다.

다음 원문 검토는 `review-queue.csv`에서 값 차이 → 컷 순서 → 전형 유형 공란 순으로 진행할 수 있다. `source_text_review` 항목은 평균·최저·비공개 등 원문 표의 지표 의미를 확인한 뒤 세부 숫자를 구조화한다. 수집 당시의 기준일 이후 원문 개정 여부는 별도 확인이 필요하다.
