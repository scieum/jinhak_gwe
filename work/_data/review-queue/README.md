# 검수 대기 자료 (review-queue)

상태: **검수 전 초안**. 여기 있는 파일은 앱 학생 화면에 나오지 않아요. 공개 파일(`app/public/data/*.json`)은 관리자 2명이 앱 검수 도구에서 승인한 뒤 **"공개 파일 내보내기"로만** 만들어요. 이 폴더의 어떤 파일도 승인·검수자·검수일을 채우지 않았고, 이용 조건은 모두 '미확인'이에요.

다시 만들기: `python app/tools/build_review_queue.py` (규칙·파서 자체 검사만: `--self-test`). 행 수는 `summary.json`.

## 무엇이 어디 있나

## 관리자가 불러오는 방법

### 입결 (관리자 › 규칙 관리 › 검수)
1. `results/index.csv`에서 검수할 대학 파일을 고른다(`non_https_units`가 0이 아닌 대학은 원문 주소부터 확인).
2. "입결 CSV 불러오기"로 `results/<대학>.csv`를 연다 → 원문(대학·학년도·원문 주소) 단위로 묶여 나온다.
3. 원문마다 원문 링크와 대조 → **이용 조건**을 정한다(수집 메타에 대학별 이용 허락 기록이 없어 모두 '이용 조건 미확인'으로 시작해요. 이 칸은 사람이 원문 사이트 약관을 보고 정해요).
4. 서로 다른 검수자 2명이 승인 → "검수 기록 내보내기"로 기록을 주고받는다 → 2명 승인 + 이용 허용인 원문만 "공개 자료 내보내기"에 들어간다.
- 출처: 모든 행에 `source_url`이 있어요(빈칸 0). 단 대구한의대학교 6건(273행)은 원문 주소가 `http://`라 도구가 "https 링크가 아니에요" 오류로 승인을 막아요. 주소를 바꿔 적지 않았어요 — 검수자가 원문을 https로 열 수 있는지 확인해 CSV를 고쳐야 해요.

### 계열표 (관리자 › 규칙 관리 › 계열표)
1. "계열표 CSV 불러오기"로 `fields-draft.csv`를 연다. 5열(대계열 포함)을 읽고, `추천근거` 열은 무시해요(4열 CSV도 계속 읽혀요).
2. 빈 칸(2,569행)은 승인을 막아요 → `추천근거`의 이유(맞는 규칙 없음 1,343 · 규칙 충돌 436 · 여러 학과 묶음 373 · 자유전공 305 · 기업 이름 112)를 보고 채우거나 행을 지운다.
3. 추천이 채워진 칸도 **규칙(학과명 키워드) 추천일 뿐**이라 대학 공식 모집단위 안내와 대조한다. 대계열은 인문·자연만(dept-tier D3), 예체능·체육처럼 나눌 수 없는 행은 비워 두었어요(비우면 학과별 구간표에 안 나와요).
4. 2명 승인 → "공개 파일 내보내기"(univ-wiki.json의 fields에 대계열 포함).
- 범위: 수집 입결의 수시 교과·종합 모집단위(+ 공개 입결이 있으면 그 모집단위). '공개 입결에서 빠진 학과 추가'와 같은 범위예요.
- 규칙 표는 `app/tools/build_review_queue.py`의 `FIELD_RULES`(학과명 정규식 → 소계열·중계열·대계열).

### 대학 위치 (관리자 › 규칙 관리 › 대학 위치)
1. "위치 초안 불러오기"로 `univ-map-draft.json`을 연다(초안의 검수자 칸은 읽지 않아요).
2. 캠퍼스를 눌러 본교·분교·학교 종류·설립·시·도·시군구·좌표를 확인해 채우고 저장한다. 칸을 고치면 그 캠퍼스의 승인이 지워져요.
3. 서로 다른 검수자 2명이 캠퍼스마다 승인 → "검수 기록 내보내기/가져오기"로 주고받는다.
4. 데이터 기준일·목록 출처를 적고 "공개 파일 내보내기" → 2명 승인 캠퍼스만 `univ-map.json`에 들어가요(승인 전 캠퍼스는 이름·개수 모두 빠져요).

### 계열 묶음 · 수능 최저 — 아직 검수 도구 없음
이 둘은 앱에 검수 화면이 없어요. 초안을 공개 파일로 옮기지 마세요(앱의 `parseUnivMap`·`parseTracks`는 검수 전 행을 핀·행으로 보이지 않게 막지만, 승인을 흉내 내면 안 돼요).

## 초안별 한계

- **대학 위치**: 목록 = 2028 전형계획(어디가) 대학·캠퍼스 218항목 + 입결만 있는 대학 6곳(대학 기준 목록). 경찰대학은 D16 1차 범위 밖이라 뺐어요. 시·도는 전형계획 지역 표기에서만 옮겼고 `전남광주` 19곳은 하나로 정할 수 없어 비웠어요. 주소·좌표·시군·설립 구분은 자료가 없어 **모두 비움(좌표 0/224)**. 학교 종류는 교육대학교 10곳 · 과학기술원·한국에너지공과대학교 4곳만 이름으로 채웠어요. 제2·제3캠퍼스는 본교·분교 법적 지위를 확인해야 해서 `campus_type`을 비웠어요. KEDI 주소록 대조 전이에요(spec 4-1 순서 1~2).
- **계열 묶음**: 학과명 규칙(메디컬·보건·교육·체육·예체능 실기·계약학과·자유전공) + 대학 기준(과기원 6곳 중 입결이 있는 5곳, 교육대학교). 계약학과 169행은 학과명(기업명·군사·국방·반도체+기업)으로만 고른 후보라 근거에 "전형계획 원문에서 채용·복무 조건 확인 필요"를 붙였어요. `plan`은 2028 구조화 전형계획 초안에서 대학·모집단위 이름이 똑같을 때만 붙였고 수능최저 유무는 `null`(원문 확인)이에요. 특수목적대는 데이터가 없어 0행(spec D7).
- **수능 최저**: `admission-plans/structured/universities/*.json`의 최저 규칙 원문 문장(source_text 등)과 `admission-plans.json` 전형 요약의 `minimum`만 읽어요. 한 문장에 기준이 하나이고 "n개 영역 합 m"·반영 영역·탐구 방식(상위 1과목|평균)이 모두 있을 때만 `parsed`. 못 읽은 이유: 모집단위·계열별 조건 혼합, 영역별 상한(각 n등급), 사회·과학을 각각 영역으로 셈, 탐구 방식 미기재 등(`summary.json`의 `unparsed_unique`). 구조화 필드만 있고 문장이 없는 규칙 약 4,400개는 이번 파서 대상이 아니에요. 판정에 쓰지 않아요(NEVER-1).
- **모의고사 등급컷**: `work/_data`에 등급컷 출처 자료가 없어 초안을 만들지 않았어요(`app/src/data/mock-exams.ts`의 `cutTables`도 비어 있음). 시험별 공식·공개 출처(교육청 채점 결과 등)를 먼저 모아야 해요.

## 필요한 검수 도구 (아직 없음 — 만들지 않았어요)

1. ~~대학 위치 검수~~ → 관리자 › 대학 위치(AdminMap)로 만들었어요. 주소록(KEDI)·좌표(공공데이터/지오코더) 일괄 불러오기는 아직 없어 좌표를 한 캠퍼스씩 적어요.
2. **계열 묶음 매핑 검수**(special-tracks spec 4-1): 행(모집단위×묶음)별 근거·세부·사실 태그 확인, 2명 승인 → `special-tracks.json`의 mapping 내보내기. 계약학과는 원문 쪽수 근거 입력 칸 필요.
3. **실기 과목·채점 기준 검수**(special-tracks spec 4-2 · D21): 모집요강 원문 옮김 + 2명 승인. 초안 없음.
4. **수능 최저 기준 검수**(minimum-search): `minimum-draft.json`의 문장↔구조화 기준 대조, 못 읽은 문장 직접 입력, 모집단위·전형 연결, 2명 승인 → 검수 완료 기준(`MinimumRule`) 공개 파일.
5. **모의고사 등급컷 검수**(mock `CutTable`): 시험·버전·기준일·출처와 영역별 컷 입력, 2명 승인.
