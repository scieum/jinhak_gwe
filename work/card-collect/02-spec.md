## 0. S2 결정 (01-research "S2 확인 필요" 두 항목)

1. **카드 받기는 PC에서만 해요.** QR은 PC 웹캠으로 읽고, 파일(.jnavi)은 PC에 끌어 놓거나 골라서 넣어요.
   - 이유: design.md Responsive Strategy "카드 수합 = 모바일 보기 전용", PRD 7-5 "학급 데이터는 교사 브라우저에만, 기기 간 동기화 없음". 휴대폰으로 받으면 카드가 휴대폰에만 남고 PC 표에는 들어오지 않아요.
   - 그래서 01-research P1의 "모바일 기본 = QR로 받기"는 쓰지 않아요. PC 기본 선택 = "파일로 받기"(교무실 PC에 카메라가 없을 수 있음).
2. **모바일은 제출 현황 보기 전용**이에요. 받기 버튼을 두지 않고 "카드는 PC에서 받아요" 안내만 둬요.
   - 모바일 프레임은 "이 기기에 학급 데이터가 있을 때"의 좁은 화면 구성이에요(좁힌 PC 창, 태블릿). 학급 데이터가 없는 휴대폰에서 열면 390-no-class 상태가 나와요(5장).
3. **새 컴포넌트를 만들지 않아요.** QR 읽기 영역·파일 넣기 영역은 `modal` 안에 이름 없는 레이어 묶음으로 그리고, 진행 막대는 `score-bar` 변형 progress, 목록·상태는 `data-table` 행, `data-status-badge`, `button-outline`으로 조합해요. 정식 컴포넌트로 올릴지는 9장 "design.md 수정 제안"에 적었어요.
4. **표의 6칸은 학생이 보낸 카드 그대로**예요. 이 화면에서 환산·판정을 새로 계산하지 않아요(NEVER-1). 판정은 학생이 카드를 보낸 때의 될각 판정이에요.

## 1. 공통 원칙

- 흰 캔버스, 1px 선과 옅은 회색 단계로 구조. 모서리 전부 0. 그림자는 `modal`, `toast`에만.
- 판정·경고·오류는 색 + 아이콘 + 이름을 함께 써요.
  - 카드 판정: `judge-badge` ● 안정 · ◐ 적정 · ▲ 소신 · ■ 위험
  - 조합 경고 개수: 소신 쌍 ▲ + "경고 n"(`judge-badge` 경고 변형, 우리 반 홈과 같음)
  - 받기 결과(바로잡음, 2026-11-24): 판정이 아니라서 판정 색을 쓰지 않아요. 받음 · 새 버전 · 건너뜀 · 읽는 중 · 확인 필요 모두 흑백 `data-status-badge` + 이름이에요. 확인 필요 줄 아래 이유 줄은 design.md "화면 오류 줄" 모양(흰 바탕 + icon/triangle-alert 16 잉크 + body-sm 잉크)이고 늘 **이유 + 고치는 법**을 한 문장으로 붙여요. (design.md: 완료 = 안정 쌍은 환산 규칙 검수에만, 읽기·저장 오류는 판정 색 없음)
  - 제출 상태(제출 · 미제출 · 새 버전 · 확정)는 판정이 아니라서 흑백 `data-status-badge` + 이름이에요. 확정은 앞에 자물쇠 아이콘.
- Route Blue
  - 숫자: 화면 전체에서 **미제출 6명 하나만** 파란 글자예요. 칩·세그먼트 안 숫자, 경고 숫자, 진행 숫자는 잉크.
  - 선택 표시: 선택된 sidebar-item(왼쪽 3px 막대), `segmented-control-active`(아래 2px 막대), sub-nav 선택 탭(아래 2px 막대), `tab-bar-pill` 선택 탭 아이콘.
  - 진행 표시: 상태 프레임의 `score-bar` 변형 progress ① 단계 진행(높이 6, Route Blue 채움)만. 주요 버튼 채움·배지 안·장식에는 쓰지 않아요.
- 학생은 "07 · 별빛"처럼 번호 · 별칭만 써요. 실명 칸·사진 칸 없음. 파일 이름에도 번호·별칭만 나와요.
- 숫자(번호, n/6장, 개수, 날짜, 장수 2/3)는 모두 고정폭 숫자, 자간 0.
- 한 줄 우선: 별칭·대학 이름·표 셀·파일 이름은 한 줄에 들어가도록 열 폭을 나눠 두었어요(아래 폭 계산). 말줄임은 모바일 목록 한 줄 요약에만 써요.
- 대학 이름은 수시로 시안과 같은 가상 이름(가온대·누리대·다솜대·라온대·마루대·새솔대·아라대·한빛대)이에요. 모든 숫자도 예시예요.

ST4와 같은 모달, 머리 "4개를 받았어요 · 6개 확인 필요"(건너뜀 2개는 따로 세지 않음), 목록에 이유 8줄(앱 domain/classroom.ts 문구 그대로):

- 확인 필요 · 모의고사 파일: "모의고사 파일이에요. 모의고사 수합에서 받아 주세요."(바로잡음: 예전 "가채점 파일" 문구 대신 앱 문구)
- 확인 필요 · 다른 종류 파일: "상담카드 파일이 아니에요. 학생이 수시로에서 '파일로 저장'한 파일을 넣어 주세요."
- 확인 필요 · 학급 코드 다름: ST4 문구
- 확인 필요 · 명단에 없음: "우리 반 명단에 31번이 없어요. 우리 반 홈에서 명단을 확인해 주세요."

## 9. design.md 수정 제안

1. QR 읽기 영역(카메라 미리보기 + 직각 1px 가이드 + 장수 진행) — 지금은 `modal` 안 이름 없는 레이어. 모의고사 수합에서도 쓸 거라 컴포넌트로 올릴지 정해 주세요.
2. 파일 넣기 영역(1px 점선 hairline + 아이콘 + 문구 + 파일 고르기 버튼 + 조건 줄, 끌어 놓는 중 · 접힘 높이 72) — 성적 불러오기·결과 집계와 같이 쓸 수 있어요. 컴포넌트 후보.
3. 받기 결과 상태 — "받음 · 읽는 중 · 확인 필요 · 건너뜀 · 새 버전"을 흑백 `data-status-badge`로 쓰고 "확인 필요"만 icon/triangle-alert 12를 붙였어요. 아이콘 붙는 규칙이 변형 self에만 있어서 "파일 받기 상태" 줄을 덧붙이는 것을 제안해요.
4. 파일별 이유 줄(표 행 바로 아래 전체 폭, 화면 오류 줄을 작게: 아이콘 16 + body-sm) — 화면 오류 줄 규칙은 목록·표 위 한 줄만 말해요. 표 행 아래 이유 줄을 허용하는 문장을 제안해요.
5. 표 안 `judge-badge` 크기(높이 20, 좌우 4) — 크기 규칙이 없어요. 학생×카드 표가 한 줄에 들어가려면 필요해요.
6. Responsive Strategy "카드 수합 모바일 = 보기 전용"에 "학급 데이터가 이 기기에 있을 때만 보여요(기기 간 동기화 없음, PRD 7-5)"를 덧붙이는 것을 제안해요.
7. 모달 위에서 확인 창이 열릴 때(받기 모달 → 닫기 확인) 두 겹으로 쌓지 않고 같은 자리에서 바꾼다는 규칙이 없어요. 이 문서는 "같은 자리에서 바뀜"으로 정했어요.
- 지난 제안 중 진행 막대 · sub-nav · sidebar-group은 design.md에 들어가서 뺐어요(`score-bar` 변형 progress, `sub-nav`, `sidebar-group`).

## 10. 넣지 않는 것

- 휴대폰으로 카드 받기(0장 결정 1), 대학별 지원자 집계 보기(PRD 6-10 — 다음 설계로 미뤄요), 교사 코멘트 응답 파일 만들기·확정 잠금 조작(학생 상담 화면 담당), 표 안 버전·받은 시각 열(학생 상담 화면 이력에서 봐요), 잠금 화면(공통 `lock-screen`, 이 화면 상태 아님).
- 실명·사진, 둥근 프레임, 브랜드 색, 어두운 토스트로 오류 알림, 확률·예측 문구.
