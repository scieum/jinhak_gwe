# 02-spec — 카드 수합 (card-collect, 교사)

- 화면: 카드 수합 (slug card-collect) · 내비 위치 = 교사 대분류 "수합·집계" › 소분류 "카드 수합"(work/_pending/apply4.py IA)
- 근거: PRD 6-10 상담카드 수합 보드(여러 개 한꺼번에 불러오기, 학생×카드 한 표, 위험 경고 학생 먼저 정렬, 버전·최종 확정 잠금), 7-3·7-5(학급 데이터는 교사 기기에만, 교환은 파일 .jnavi 또는 QR, 실시간 동기화 없음), 8장 교환 파일(kind = counsel_card, 학급 코드로 묶음), R-PRIV-003(번호·별칭)
- 카드 내용: work/susiro/02-spec.md(6회 제한 n/6장, 판정 4종, 경고 R-CARD-002·003)
- 레퍼런스: 01-research.md 반영 포인트 P1~P9
- 프레임: 모바일 390×844, PC 1440×900 + 상태 프레임 7개(5장)
- 필수 컴포넌트: card-collect는 requires_* 대상이 아니에요. 다만 학생 카드의 판정과 대학 이름이 표에 나오므로 `disclaimer-note`를 넣어요.

## 0. S2 결정 (01-research "S2 확인 필요" 두 항목)

1. **카드 받기는 PC에서만 해요.** QR은 PC 웹캠으로 읽고, 파일(.jnavi)은 PC에 끌어 놓거나 골라서 넣어요.
   - 이유: design.md Responsive Strategy "카드 수합 = 모바일 보기 전용", PRD 7-5 "학급 데이터는 교사 브라우저에만, 기기 간 동기화 없음". 휴대폰으로 받으면 카드가 휴대폰에만 남고 PC 표에는 들어오지 않아요.
   - 그래서 01-research P1의 "모바일 기본 = QR로 받기"는 쓰지 않아요. PC 기본 선택 = "파일로 받기"(교무실 PC에 카메라가 없을 수 있음).
2. **모바일은 제출 현황 보기 전용**이에요. 받기 버튼을 두지 않고 "카드는 PC에서 받아요" 안내만 둬요.
   - 모바일 프레임은 "이 기기에 학급 데이터가 있을 때"의 좁은 화면 구성이에요(좁힌 PC 창, 태블릿). 학급 데이터가 없는 휴대폰에서 열면 ST5-M 빈 상태가 나와요.
3. **새 컴포넌트를 만들지 않아요.** QR 읽기 영역·파일 넣기 영역·진행 막대는 `modal` 안에 이름 없는 레이어 묶음으로 그리고, 목록·상태는 `data-table` 행, `data-status-badge`, `judge-badge` 모양, `button-outline`으로 조합해요. 정식 컴포넌트로 올릴지는 7장 "design.md 수정 제안"에 적었어요.
4. **표의 6칸은 학생이 보낸 카드 그대로**예요. 이 화면에서 환산·판정을 새로 계산하지 않아요(NEVER-1). 판정은 학생이 카드를 보낸 때의 될각 판정이에요.

## 1. 공통 원칙

- 흰 캔버스, 1px 선과 옅은 회색 단계로 구조. 모서리 전부 0. 그림자는 `modal`, `toast`에만.
- 판정·경고·오류는 색 + 아이콘 + 이름을 함께 써요.
  - 카드 판정: `judge-badge` ● 안정 · ◐ 적정 · ▲ 소신 · ■ 위험
  - 조합 경고 개수: 소신 쌍 ▲ + "경고 n"(`judge-badge` 경고 변형, 우리 반 홈과 같음)
  - 받기 결과: ● 받음 = 안정 쌍(design.md "완료 = 안정 쌍") / ■ 확인 필요 = 위험 쌍(design.md "입력 오류 = 위험 쌍"). 오류 줄은 늘 **이유 + 고치는 법**을 한 문장으로 붙여요.
  - 제출 상태(제출 · 미제출 · 새 버전 · 확정)는 판정이 아니라서 흑백 `data-status-badge` + 이름이에요. 확정은 앞에 자물쇠 아이콘.
- Route Blue
  - 숫자: 화면 전체에서 **미제출 6명 하나만** 파란 글자예요. 칩·세그먼트 안 숫자, 경고 숫자, 진행 숫자는 잉크.
  - 선택 표시: 선택된 sidebar-item(왼쪽 3px 막대), `segmented-control-active`(아래 2px 막대), sub-nav 선택 탭(아래 2px 막대), `tab-bar-pill` 선택 탭 아이콘.
  - 진행 표시: 상태 프레임의 진행 막대(높이 4)만. 주요 버튼 채움·배지 안·장식에는 쓰지 않아요.
- 학생은 "07 · 별빛"처럼 번호 · 별칭만 써요. 실명 칸·사진 칸 없음. 파일 이름에도 번호·별칭만 나와요.
- 숫자(번호, n/6장, 개수, 날짜, 장수 2/3)는 모두 고정폭 숫자, 자간 0.
- 한 줄 우선: 별칭·대학 이름·표 셀·파일 이름은 한 줄에 들어가도록 열 폭을 나눠 두었어요(아래 폭 계산). 말줄임은 모바일 목록 한 줄 요약에만 써요.
- 대학 이름은 수시로 시안과 같은 가상 이름(가온대·누리대·다솜대·라온대·마루대·새솔대·아라대·한빛대)이에요. 모든 숫자도 예시예요.

## 8. design.md 수정 제안

1. QR 읽기 영역(카메라 미리보기 + 직각 1px 가이드 + 장수 진행) — 지금은 `modal` 안 이름 없는 레이어. 가채점 수합에서도 쓸 거라 컴포넌트로 올릴지 정해 주세요.
2. 파일 넣기 영역(1px 점선 hairline + 아이콘 + 문구 + 파일 고르기 버튼 + 조건 줄) — 성적 불러오기·결과 집계와 같이 쓸 수 있어요. 컴포넌트 후보.
3. 진행 막대(높이 4, canvas-soft 트랙 + Route Blue 채움) — design.md는 "진행 표시"에 Route Blue를 허용하지만 모양 규칙이 없어요.
4. 받기 결과 배지 — ● 받음 = 안정 쌍, ■ 확인 필요 = 위험 쌍으로 `judge-badge` 모양을 재사용했어요. "상태 배지에 judge-badge 색 쌍 재사용" 문장이 design.md에 없어요(성적 불러오기 02-spec과 같은 제안).

6. Responsive Strategy "카드 수합 모바일 = 보기 전용"에 "학급 데이터가 이 기기에 있을 때만 보여요(기기 간 동기화 없음, PRD 7-5)"를 덧붙이는 것을 제안해요.
