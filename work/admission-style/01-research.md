## 0. 이 화면이 하는 일 — 앱 구현에서 찾은 기능 · 상태 · 팝업

### 0-1. 단계와 블록 (구현됨)

| 단계 | 블록 | 내용 |
|---|---|---|
| intro | 상단 줄 | "나의 준비 방식 찾기" · "체험판 · v0.1" |
| intro | 히어로 | 눈썹 "성적표 밖의 나도 만나볼까요?", 제목 "나에게 맞는 입시의 시작점.", 사실 3개(15문항 · 약 3분 · 가입 없이), 시작 버튼 "나의 전형 성향 알아보기", 저장 안 함 안내, 캐릭터 길콩 + 캡션 |
| intro | 준비 방식 5개 | 01~05 카드(매일의 힘 · 질문의 힘 · 논리의 힘 · 표현의 힘 · 집중의 힘 + 유형 이름). 누를 수 없음 |
| intro | 고지 | "직접 만든 자기탐색 질문 · 표준화 검사 아님 · 지원 자격이나 입학 결과를 판단하지 않음" |
| quiz | 왼쪽 안내 | 길콩 + "멋진 답보다 지금의 나와 가까운 답." + "경험이 없다면 마지막 선택지" |
| quiz | 문항 패널 | "나를 알아가는 중" · n / 15, 진행 막대, 문항 제목, 선택지 5개(거의 그렇지 않아요 / 가끔 그래요 / 자주 그래요 / 매우 그래요 / 아직 경험이 없거나 잘 모르겠어요), 오른쪽 표시 01~05 → 고르면 ✓ |
| quiz | 컨트롤 | 왼쪽 보조 버튼(1번 문항 "소개로", 그 외 "이전 문항") · 오른쪽 주 버튼("다음 문항", 15번은 "내 성향 보기") |
| result | 히어로 | 눈썹 "지금 답변에서 발견한 나", 유형 이름, 설명 1문단, 결과별 길콩 |
| result | 카드 목록 | 머리 "NEXT STEP · 함께 살펴볼 전형"(후보 없으면 "경험해 볼 준비 방식"). 카드 = 눈썹(탐색 추천 / 아직 열려 있는 길) · 전형 이름 · 설명 · "이 답변을 참고했어요" 불릿(긍정 응답 문장) · "다음 확인" |

| result | 행동 4개 | 실제 성적 확인하기 → /grade-input · 대학별 환산 살펴보기 → /univ-score · 답변 돌아보기(1번 문항으로, 답 유지) · 처음부터 다시(답 전부 지우고 소개로) |
| result | 고지 | 탐색 안내일 뿐 · 심리검사 · 상담 대체 아님 · 서버 전송 없음 |

### 0-2. 상태 (S2 상태 프레임 후보)

| # | 상태 | 조건(구현) |
|---|---|---|

| S-2 | 문항 · 아직 안 고름 | 해당 문항 답 없음 → 주 버튼 disabled |
| S-3 | 문항 · 고름 | 선택지 1개 is-selected + ✓ |

| S-8 | 결과 · open | 모든 평균 2 미만 → "가능성을 열어 둔 탐색가", 5개 축 카드 "아직 열려 있는 길" |

### 0-3. 팝업 · 확인 창 (구현 현황)

- 이 화면에는 Modal · 확인 창 · bottom-sheet · toast가 **하나도 없어요**. `confirm()`도 없어요.
- "처음부터 다시"는 확인 없이 15개 답을 바로 지워요. 탐색 중 다른 메뉴로 나가도 경고 없이 답이 사라져요(메모리 상태).
- summarizeStyle은 미응답이 있으면 오류를 던지지만, 주 버튼 disabled 때문에 화면에서는 나오지 않아요.

### 0-4. 아직 안 그린 · 안 만든 기능 (exploration.md "남은 확장" + 구현 빈칸)

1. 결과 저장 · 공유 카드 다운로드 (없음)
2. 유형별 캐릭터 포즈 (StyleMascot kind 분기는 있으나 포즈 자산 추가 예정)
3. 실제 성적과 결합한 전형 검색 (없음 — 성향과 검수된 조건을 별도 축으로만)
4. 준비 방식 5개 카드 눌러 자세히 보기 (없음)
5. 답변 한눈에 보기 · 특정 문항으로 바로 가기 (없음, "답변 돌아보기"는 1번부터 다시 넘김)

## 2. 반영 포인트

- P1: 소개는 한 화면에 "제목 · 회색 설명 1문단 · 사실 3개 · 옅은 고지 · 검정 주 버튼 하나"만 둬요. 준비 방식 5개 카드는 그 아래 두되, 누르면 그 준비 방식 설명을 `bottom-sheet`(PC `modal`)로 여는 새 상태를 그려요(구현에 없는 기능 0-4 ④) [근거: L1, L7]
- P2: 문항 화면은 "진행 막대 + n / 15 → 굵은 문항 → 세로 선택지 5개 → 아래 이전 · 다음"으로 고정해요. 고른 선택지만 Route Blue 1px 테두리 + Route Blue Soft 채움(design.md "선택됨"), 안 골랐을 때 다음 버튼은 비활성 회색. 상태 프레임 S-2 · S-3 · S-4 · S-5를 각각 그려요 [근거: L3, L5, L4]
- P3: "아직 경험이 없거나 잘 모르겠어요"는 5번째 선택지로 같은 모양에 두되 위에 얇은 구분선을 둬서 척도 4개와 성격이 다름을 보여요. 숫자 점수(0~3)는 화면에 쓰지 않아요 [근거: L3, L4]
- P4: 결과 히어로는 "눈썹 → 캐릭터 → 유형 이름 → 한 줄 요약" 카드 하나로 묶어요. 하위 점수 · 평균 · 백분위 · 큰 숫자 · "○○ 높음" 같은 판정 문구는 넣지 않아요(NEVER-2, 검증 안 된 임시 규칙). 결과 4종(focused · mixed · open · insufficient)을 각각 상태 프레임으로 그리고, 판정 색(안정/적정/소신/위험)은 쓰지 않아요 [근거: L6, L8]
- P5: 결과 아래 "함께 살펴볼 전형" 카드는 2열(모바일 1열) 작은 카드로, 카드마다 "이 답변을 참고했어요" 근거 문장 불릿과 "다음 확인"을 둬요. "결과는 어떻게 정했나요?"는 `trace-accordion` 또는 `disclaimer-note` 위쪽 회색 블록으로, 탐색 안내 · 대학 공식 자료 확인 문구를 불릿으로 적어요 [근거: L7, L6]
- P6: "처음부터 다시"는 바로 지우지 말고 확인 창을 띄워요: `modal`(PC) / `bottom-sheet`(모바일), 제목 "답변을 모두 지울까요?" + 결과 1줄 "15개 답변이 지워지고 처음으로 돌아가요" + 버튼 2개(외곽선 "취소" / 주 버튼 "지우고 다시 하기"). 지운 뒤 `toast` "답변을 지웠어요" [근거: L9, L10]
- P7: 문항 도중 앱바 뒤로 · 다른 메뉴로 나갈 때 확인 `bottom-sheet`를 그려요: "탐색을 그만둘까요?" + "답변은 저장하지 않아서 나가면 사라져요"(구현 사실). 주 버튼은 "계속 답하기", 그만두기는 아래 텍스트 버튼. 저장을 안 하므로 L2식 "이어서 하기" 창은 그리지 않고 S2 미결로 남겨요 [근거: L11, L10, L2]
- P8: 결과 공유는 `share-sheet`로 그려요: 결과 카드 이미지 미리보기 + "이미지 저장" · "링크 복사" 대신 기기 공유만. 공유 이미지에는 유형 이름 · 탐색 전형 · "자기탐색 체험판 결과예요" 고지를 넣고 근거 문장 · 답변은 빼요(서버 전송 없음 원칙). 구현에 없는 기능 0-4 ①이라 S2에서 범위 확정 [근거: L6, L7]
- P9: "답변 돌아보기"를 1번부터 넘기는 대신 15개 문항 · 내 답 요약 목록 `bottom-sheet`(PC `modal` size=wide)로 열고, 행을 누르면 그 문항으로 바로 가는 상태를 추가로 그려요(0-4 ⑤) [근거: L5, L3]

## 4. S2 주의 · 미결

1. 색: 앱 구현은 탐색 화면에 한해 연보라 · 민트 · 살구 · 크림 · 연한 하늘색 장식 배경을 써요(admission-style.css). 이 색들은 design.md 팔레트에 없어서 Figma에 그대로 옮기면 J1(팔레트 밖 색) · J7(토큰 미연결)에 걸려요. 팔레트 안 회색 단계로 그릴지, "design.md 수정 제안"으로 멈출지 S2에서 정해 주세요.
2. 캐릭터 길콩 PNG · 둥근 일러스트: 이미지 채움이면 J2(모서리) 대상이 아닐 수 있지만, 판정 스크립트가 이미지 노드를 어떻게 세는지 S2/S3에서 확인 필요.
3. 금지어: 구현의 규칙 펼침 마지막 문장에 rules `forbidden_words`와 같은 뜻의 단어(띄어쓰기만 다름)가 들어 있어요. G2 · J8은 띄어쓰기 형태만 셀 수 있지만 NEVER-2 취지상 시안에서는 문장을 바꿔 주세요(예: "결과를 성적이나 입학 결과 예측으로 바꾸지 않아요").
4. "탐색 추천" 눈썹 · "NEXT STEP" 영문 눈썹이 design.md Voice와 맞는지 S2 확인.
5. 공유(P8) · 답변 요약(P9) · 준비 방식 시트(P1)는 구현에 없는 새 기능이에요. 시안에 그리되 "앱 미구현" 라벨을 프레임 이름에 붙일지 S2 결정.
6. requires_trace_accordion 대상 여부: 이 화면은 성적 환산 계산이 없어요. 규칙 설명을 `trace-accordion`으로 쓸지 rules/design-rules.json으로 판단해 주세요. 이 slug는 아직 rules `screens`에 없어요(오케스트레이터 · 사람 몫).
7. 캐릭터 · 진행 막대 · 라디오 선택지 전용 컴포넌트가 design.md에 없어요. `subject-card` · `filter-chip` · `segmented-control` 등 기존 컴포넌트로 표현이 안 되면 새로 만들지 말고 "design.md 수정 제안"으로 멈춰 주세요.
8. uibowl 한계: 교육 입시 앱 성향 검사 0건, 무료 범위라 그룹당 대표 화면 1장만 직접 봤어요(L6 하위 점수 · L1 버튼 위치 등은 대표 화면 기준).
