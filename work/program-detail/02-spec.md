## 2. 모바일 390 × 844

앱 셸: 상단 앱바 56px(왼쪽 뒤로가기, 가운데 제목 "전형 상세" heading-4) + 하단 `tab-bar-pill`(메뉴 탭 선택 상태, 전형계획은 메뉴 안에 있으므로).
좌우 패딩 16px, 콘텐츠 폭 358px, 섹션 간격 32px. 프레임은 390×844 그대로 두고, 첫 화면 아래 내용은 프레임 안 세로 스크롤 영역으로 이어 그려요.

1. S1 머리
   - 왼쪽 `univ-monogram`(48px, "한") + 오른쪽 대학명 "한빛대학교"(heading-3), 아래 전형명 "학생부교과(학교장추천)"(heading-4, 길면 두 줄).
   - 그 아래 한 줄: 전형 유형 caption "수시 · 교과 · 학교장추천" + `data-status-badge` "시행계획 기준".

2. S2 핵심 요약 — `stat-tile` 2×2 그리드(타일 폭 171px, 간격 16px)

3. S3 지원자격 — 섹션 제목 heading-2 "지원자격", `data-table` 라벨-값 2열

## 4. 상태

- `data-status-badge` 문구 4가지: "시행계획 기준" / "모집요강 반영" / "환산 규칙 검수 완료" / "환산 규칙 준비 중". 모두 흑백 알약, 판정 색 쓰지 않아요.
- 수능최저 없음: S2 타일 값 "없음", S5는 표 대신 body 한 줄 "이 전형은 수능최저학력기준이 없어요".
- 단계 1개(일괄 선발): S2 "일괄", S4 표는 한 행만.
- 일정 미정: 날짜 칸에 "모집요강 발표 후 안내"(text-muted).

## 5. 문구 규칙

- 해요체로 써요. 사실만 적고, 합격을 약속하거나 결과를 수치로 단정하는 표현은 쓰지 않아요.
- 숫자·날짜는 모두 고정폭. 색은 쓰지 않아요(이 화면에는 내 위치·판정이 없어서 Route Blue와 판정 색이 나오지 않아요).

## 6. 리서치 반영 메모

- P3 비율 막대: design.md에 해당 컴포넌트가 없어서 새 이름을 만들지 않고, S4 `data-table`의 숫자 열 + 표 위 요약 문장으로 표현해요. 수정 제안은 하지 않아요.
- P4 세로 타임라인: 상담 메모용 컴포넌트를 다른 뜻으로 쓰지 않도록 S7은 `data-table`로 그려요.
- P5 펼치는 아코디언 행: 일반 아코디언 컴포넌트가 없어서 수능최저 원문을 접지 않고 표 아래 문장으로 바로 보여줘요.
- P6의 상단 "관심 담기" 외곽선 버튼은 PC 패널의 주요 버튼과 겹쳐서 빼요.

## 7. design.md 수정 제안

- `data-table` 모바일 규칙 보완: 지금은 "모바일에서는 카드 목록으로 바뀐다"인데, 읽는 화면의 짧은 표(4열 이하, 라벨-값 표 포함)는 모바일에서도 표로 유지하도록 예외를 두면 좋겠어요. 이 설계서의 모바일 S3~S7이 이 예외를 전제로 해요. 받아들이지 않으면 S3·S5·S6·S7은 표 대신 "라벨(caption) → 값(body)" 문장 줄로, S4는 `stat-tile`(교과 100% 등)로 바꿔요.

## 8. 디자이너 메모

- 프레임 2개: program-detail/390 (390×844), program-detail/1440 (1440×900). 이 밖의 프레임은 만들지 않아요.
- 레이어 이름 = 컴포넌트 이름(예: 레이어 "stat-tile", "data-table"). 컴포넌트가 아닌 묶음은 섹션 번호(S1~S9)로 이름 붙여요.
- 알약 모양(버튼, 배지, 탭바, 사이드바 선택 메뉴, 토스트)은 radius 9999. 카드·보조 패널 24, 표 컨테이너 16, 표 셀 0. `univ-monogram`만 radius 예외예요.
- 그림자는 `toast`에만. 카드·버튼·패널·사이드바에는 넣지 않아요.
- 색은 팔레트 변수에 바인딩하고, 이 화면에서는 흑백(ink, ink-soft, text-muted, canvas, canvas-soft, field, hairline)만 써요.
- 글꼴 Pretendard(300/400/600/700), 자간 0, 숫자는 tabular-nums.
