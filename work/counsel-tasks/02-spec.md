## 4. 규칙 · 데이터

- 데이터는 앱 CounselTask 그대로예요: 구분(상담 전 질문 / 상담 후 할 일) · 제목(필수, 200자) · 연결할 전형(없으면 공통 상담) · 상담일(선택) · 기한(선택) · 메모(2000자) · 완료 여부 · 완료 시각. 새 필드 없어요.
- 기한 표시는 한국 날짜(오늘 = 서울 날짜) 기준: 완료면 "완료", 기한 없으면 "기한 없음", 오늘보다 앞이면 "기한 지남", 오늘이면 "오늘까지", 뒤면 "예정". 날짜 뒤에 " · MM-DD까지".
- 완료 시각 표기(기본안): "완료 · 2026-11-13 오후 4:20"(고정폭 숫자, 초는 빼요). 앱은 기기 로캘 표기("2026. 11. 13. 오후 4:20:00")예요.
- 이 화면은 계산 · 환산 · 판정이 없어요(NEVER-1 해당 없음). 질문 예시 · 안내 문구에 합격을 약속하거나 확률로 읽히는 말을 쓰지 않아요(NEVER-2).
- 저장 위치: 이 기기(IndexedDB) · 암호화 백업에 포함. 교사에게 자동으로 가지 않아요. 학생이 고른 질문만 상담카드 "고민 메모"에 담겨 QR · 파일(.jnavi)로 전달돼요(K1). 담은 질문은 이 화면에서 지워지거나 완료되지 않아요.

## 7. 접근성

- 칩 줄: 상태 칩 3개 = 라디오 묶음("상태, 진행할 항목 6개 선택됨"). "구분 ▾" · "전형 ▾"는 팝업 버튼("구분, 전체, 목록 열기"). 거르기를 바꾸면 "항목 2개"를 조용한 알림으로 읽어요.
- 카드 읽기 순서: 제목 → 구분 · 전형 · 상담일 → 기한 → 메모 → 버튼. 기한 상태는 글자로 읽혀요("기한 지남, 11월 19일까지") — 굵기 · 아이콘에 기대지 않아요. 버튼 이름에 제목을 붙여 읽어요("면접 예상 질문 10개 적어 오기 완료로 표시").
- 오류 줄 · 제목 오류는 role=alert(아이콘 + 글자, 색에 기대지 않음). 제목 오류는 입력칸과 연결(aria-describedby)하고 저장을 누르면 제목 칸으로 포커스가 가요. 토스트 · 읽는 중은 role=status.
- 시트 · 모달은 열면 제목으로 포커스, Esc · 닫기로 닫고 닫으면 누른 버튼으로 돌아가요. 저장 · 삭제 중에는 닫기 · Esc · scrim이 막혀요. 하위 시트(390-add-plan)를 닫으면 "연결할 전형" 행으로 포커스.
- 삭제 확인은 alertdialog, 처음 포커스는 "취소".
- 상담카드 고르기(390-share-pick · 1440-share-pick) 행은 체크 상자 역할("면접 준비… , 선택됨"), 주요 버튼은 고른 개수를 읽어요("고른 3개 담기"). "물어봤어요" 버튼도 제목을 붙여 읽어요.
- 모바일 누르는 곳 44 이상(칩 터치 44, 카드 버튼 44, 시트 행 48), PC 버튼 40 · 칩 32 이상. 포커스 2px 잉크 링. 날짜 · 숫자 고정폭.
- 글자 대비: 완료 카드 제목 {colors.text-muted} 4.9:1, 비활성 글자 {colors.text-faint}는 비활성에만. 시트 · 모달 240ms, 토스트 200ms, prefers-reduced-motion이면 바로.
