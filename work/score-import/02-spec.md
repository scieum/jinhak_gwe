작성 2026-11-18 · 담당 planner · 근거: 01-research.md(P1~P6), docs/prd.md 6-2·6-10·7-3·13장, work/_pending/apply.py PRD_SECTION(성적 불러오기), work/_ref/schs_lms-homeroom.md 3(b), docs/design.md

## 1. 화면 개요
- 프레임: score-import/390(390×844), score-import/1440(1440×900). 둘 다 **3단계 검증** 상태를 그린다.
- 흐름: 파일 → 열 맞추기 → 검증 → 반영(4단계). 이 프레임은 3번째 "검증"이 선택된 상태다.
- 상황(가상): 3학년 2반 30명, 2026년 10월 학평 모의고사 등급 파일(30행)을 올리고 열 맞추기를 마쳤다. 검증 결과 정상 26행, 확인 필요 3행(빈 칸), 오류 1행(범위 오류). 범위 오류 행은 빼고 29명을 반영할 수 있다.
- 모의고사 입력 항목: 시험(연·월·종류 학평/모평/수능), 영역별 등급(국어·수학·영어·한국사·탐구1·탐구2, 필수), 원점수·백분위(선택).
- 학생은 번호·별칭으로만 표시한다(PRD R-PRIV-003). 실명 열 없음. 모든 수치는 가상이다.
- 이 화면에는 환산·판정이 없다. 검증 상태만 보여 준다.

## 2. 공통 규칙
- 모서리 0, 흑백 바탕, 1px 선으로 구조. 그림자 없음(떠 있는 레이어 없음).
- 색은 세 곳에만:
  - 검증 상태 색 쌍: 정상 = 안정 쌍 ● / 확인 필요 = 소신 쌍 ▲ / 오류 = 위험 쌍 ■. 항상 색 + 아이콘 + 이름을 함께 쓴다.
  - Route Blue: 단계 표시의 현재 단계, 선택된 필터, 사이드바 선택 메뉴, 핵심 숫자 1개("반영 예정 29명").
  - 주요 버튼은 잉크 채움. Route Blue로 채우지 않는다.
- 등급 숫자에는 색을 넣지 않는다. 오류 셀은 칸 배경만 위험 bg, 빈 칸은 칸 배경만 소신 bg로 채우고 숫자·기호는 잉크.
- 숫자(번호, 등급, 행 수, 날짜)는 모두 고정폭 숫자.
- 문구는 해요체. 오류 문구는 무엇이 틀렸고 어떻게 되는지 함께 쓴다.

## 5. 상태·동작 규칙 (프레임에는 기본 상태만 그린다)
- 상태 분류(schs_lms 3(b) 6종을 3가지로 묶음):
  - ● 정상: 그대로 반영.
  - ▲ 확인 필요: 빈 칸 — 결시로 반영.
  - ■ 오류: 범위 오류(1~9 밖) — 그 행만 빼고 반영. 별칭 불일치 / 명단에 없음 / 번호 중복 — 전체 반영을 막는다.
- 전체 반영을 막는 오류가 1행이라도 있으면 `button-primary`를 비활성(text-faint)으로 바꾸고 `warning-callout` 제목을 "번호·별칭이 명단과 다른 행이 N개 있어요. 고쳐서 다시 올려야 반영돼요"로 바꾼다.
- 같은 시험을 이미 반영한 적이 있으면 시험·파일 줄 아래 caption "10월 학평은 이미 N명 반영돼 있어요. 다시 반영하면 새 값이 쓰여요".
- 파일에 없는 학생이 있으면 요약 caption "파일에 없는 학생 N명 (전체 30명)".
- "29명 반영하기"를 누르면 4단계 반영 완료로 넘어간다(이 프레임 범위 밖).
