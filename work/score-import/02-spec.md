## 1. 화면 개요
- 프레임: score-import/390(390×844), score-import/1440(1440×900). 둘 다 **3단계 검증** 상태를 그린다. 나머지 단계 · 오류 · 확인 창은 5-1 상태 프레임(34장)으로 그린다.
- 흐름: 파일 → 열 맞추기 → 검증 → 반영(4단계). 이 프레임은 3번째 "검증"이 선택된 상태다.
- 상황(가상): 3학년 2반 30명, 2026년 10월 학평 모의고사 등급 파일(30행)을 올리고 열 맞추기를 마쳤다. 검증 결과 정상 26행, 확인 필요 3행(빈 칸), 오류 1행(범위 오류). 범위 오류 행은 빼고 29명을 반영할 수 있다.
- 모의고사 입력 항목: 시험(연·월·종류 학평/모평/수능), 영역별 등급(국어·수학·영어·한국사·탐구1·탐구2, 필수), 원점수·백분위(선택).
- 학생은 번호·별칭으로만 표시한다(PRD R-PRIV-003). 실명 열 없음. 모든 수치는 가상이다.
- 이 화면에는 환산·판정이 없다. 검증 상태만 보여 준다.

## 2. 공통 규칙
- 모서리 0, 흑백 바탕, 1px 선으로 구조. 그림자 없음(떠 있는 레이어 없음).
- 색은 세 곳에만:
  - 검증 상태: 확인 필요 = 소신 쌍 ▲(경고) / 오류 = 위험 쌍 ■(입력 오류). 항상 색 + 아이콘 + 이름을 함께 쓴다. 정상은 흑백 글자(색 · 아이콘 없음).
  - Route Blue: 단계 표시의 현재 단계, 선택된 필터, 사이드바 선택 메뉴, 핵심 숫자 1개("반영 예정 29명").
  - 주요 버튼은 잉크 채움. Route Blue로 채우지 않는다.
- 등급 숫자에는 색을 넣지 않는다. 오류 셀은 칸 배경만 위험 bg, 빈 칸은 칸 배경만 소신 bg로 채우고 숫자·기호는 잉크.
- 숫자(번호, 등급, 행 수, 날짜)는 모두 고정폭 숫자.
- 문구는 해요체. 오류 문구는 무엇이 틀렸고 어떻게 되는지 함께 쓴다.
