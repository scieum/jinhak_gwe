# 02-spec — 대학별 환산 (univ-score)

> 근거: work/univ-score/01-research.md(P1~P6), docs/prd.md 6-4 · R-CALC-002/003/004/005, docs/design.md(Responsive Strategy "대학별 환산" 행), docs/story-service.md NEVER-1 · NEVER-2
> 대상 화면은 rules/design-rules.json의 requires_trace_accordion, requires_disclaimer_note 둘 다에 들어 있다. 그래서 `trace-accordion`, `disclaimer-note`를 반드시 넣는다.
> 대학명은 모두 가상이다(가람대학교 · 솔빛대학교 · 너울대학교 · 다온대학교).

## 1. 화면 목적과 데이터

- 목적: 같은 성적이 관심 대학마다 교과·출결·합계 몇 점이 되는지 보고, 계산 근거를 단계별로 확인하게 한다(PRD 6-4).
- 계산은 검수 완료(verified) 규칙만 쓴다. 검수 전 규칙인 대학은 목록에 남기되 계산하지 않는다(R-CALC-002, NEVER-1).
- 순위 정의(화면 문구로도 보여준다)
  - 환산 기준 순위: 대학 만점 대비 내 합계 비율로 줄 세운 순서
  - 단순 평균 기준 순위: 대학별 반영 교과의 단순 평균 등급으로 줄 세운 순서
  - 순위 차이 = 단순 평균 기준 순위 − 환산 기준 순위 (+면 이 대학 환산이 나에게 유리한 쪽)

### 예시 데이터 (두 프레임 공통)

| 대학 | 전형 | 교과 | 출결 | 합계 / 만점 | 만점 대비 | 반영 교과 평균 | 단순 평균 순위 → 환산 순위 | 순위 차이 |
|---|---|---|---|---|---|---|---|---|
| 솔빛대학교 | 학생부교과(지역인재) | 939.93 | 49.00 | 988.93 / 1,000 | 98.89% | 1.81 | 3위 → 1위 | +2 |
| 너울대학교 | 학생부교과(교과우수자) | 276.00 | 20.00 | 296.00 / 300 | 98.67% | 1.75 | 2위 → 2위 | 0 |
| 가람대학교 | 학생부교과(학교장추천) | 383.20 | 10.00 | 393.20 / 400 | 98.30% | 1.62 | 1위 → 3위 | −2 |
| 다온대학교 | 학생부교과(지역균형) | (빈칸) | (빈칸) | (빈칸) | — | — | — | — |

- 다온대학교 = 검수 전 규칙. 점수 칸은 비우고 숫자·추정값·임시값을 넣지 않는다. 그 자리에 `data-status-badge` "환산 규칙 준비 중" + "검수가 끝나면 계산해요"만 둔다.
- 정렬 기본값은 환산 기준 순위. 준비 중인 대학은 어떤 정렬에서도 맨 아래.
- 순위 차이에는 판정 색을 쓰지 않는다. 흑백 텍스트 "+2" / "0" / "−2"만 쓴다(P3).

### 산출 근거 예시 (솔빛대학교, 두 프레임 공통)

| 단계 이름 | 수식 / 값 |
|---|---|
| 적용 규칙 | 솔빛대학교 2028 학생부교과 규칙 v2 · 검수 완료 |
| 반영 학기 | 1-1 ~ 3-1, 5개 학기 · 학년 가중 없음 |
| 반영 과목 | 국어·수학·영어·사회·과학 22과목, 학점 합 92 |
| 제외한 과목 | 융합선택 2과목(석차등급 미산출 → 규칙상 제외) |
| 과목별 적용 점수 (예) | 공통국어1 1등급 → 100점 × 4학점 / 공통수학1 2등급 → 96점 × 4학점 / 통합과학1 1등급 → 100점 × 3학점 |
| 석차등급 점수 학점 가중 평균 | 9,089.6 ÷ 92 = 98.80 |
| 성취도 점수 학점 가중 평균 | 9,154.0 ÷ 92 = 99.50 |
| 등급·성취도 반영 | 98.80 × 0.8 + 99.50 × 0.2 = 98.94 |
| 교과 환산 (만점 950) | 98.94 × 9.5 = 939.93 |
| 출결 | 미인정 지각 3회 → 결석 1일, 미인정 결석 1일 → 결석 2일 → 구간 2~3일 −1.00 → 50 − 1 = 49.00 |
| 최종 합계 (굵게, 위 1px 선) | 939.93 + 49.00 = 988.93 / 1,000 · 소수 셋째 자리에서 반올림 |

- 중간 단계는 반올림하지 않은 값으로 계산하고 표시만 둘째 자리까지 한다(R-CALC-004).
- 출결은 지각·조퇴·결과 → 결석 환산을 먼저, 그다음 구간표를 적용한 순서대로 적는다(R-CALC-005).

## 4. 빈 상태·예외 (프레임에는 그리지 않음)

- 관심 대학 0곳: 목록/표 자리에 `empty-state` — 흑백 선 아이콘, heading-4 "아직 담은 대학이 없어요", body-sm "관심 대학을 담으면 대학마다 환산점수를 계산해 드려요", `button-primary` "관심 대학 담기" 하나(P6)
- 관심 대학 1곳: 카드/행 1개는 그대로 보여주고, 유불리 문장·순위 차이 자리에 "대학을 2개 이상 담으면 유불리를 비교할 수 있어요". 담을 칸은 `susi-slot` 빈 칸과 같은 점선 모양
- 성적 미입력: `empty-state` "아직 입력한 성적이 없어요" + `button-primary` "성적 입력하기"
- 모든 대학이 준비 중: 카드/행 모두 준비 중 모양. `stat-tile` 계산 완료 0. 순위 문장 없음
- 계산 대상 규칙의 review_status가 verified가 아니면 어떤 경로로도 숫자를 만들지 않는다(NEVER-1)

## 7. design.md 수정 제안 (제안만, 이 단계에서 고치지 않음)

1. univ-card에 "환산용 변형" 정의 추가: 오른쪽 위 판정 배지 대신 데이터 상태 배지(준비 중일 때만), 핵심 숫자 = 교과·출결·합계 3칸, 하단 "수시로에 담기" 버튼 없음. 지금 문서에는 될각용 구성만 있다.
2. 모바일 탭바에서 대학별 환산의 위치가 정해져 있지 않다. 이 설계서는 "성적" 탭 아래로 가정했다.
3. "완료·검수 완료는 안정 색 쌍" 문장과 "데이터 상태 배지는 판정 색을 쓰지 않는다" 문장이 충돌할 수 있다. 이 설계서는 검수 완료 배지를 쓰지 않고 흑백 상태 배지만 쓴다.
4. (harness-gates.md 쪽) G3가 프레임 2개만 허용해서 모바일 상세(산출 근거 아코디언 펼침)를 Figma로 그릴 자리가 없다. 상태 프레임을 허용할지 정해야 한다.

## 8. 디자이너 메모

- 레이어 이름 = 컴포넌트 이름. 예: 카드 레이어는 univ-card, 배지는 data-status-badge, 아코디언은 trace-accordion, 고지는 disclaimer-note. 여러 개면 뒤에 대학명을 붙인다(univ-card / 솔빛대학교).
- 알약(버튼, 배지, 탭바, 모드 전환, 정렬 버튼) cornerRadius = 9999. 카드 24, 표 컨테이너·아코디언 16, 표 셀 0. univ-monogram만 30% 스퀴클 예외.
- 프레임은 univ-score/390, univ-score/1440 두 개만.
- 색: 이 화면에는 판정이 없으므로 판정 4색과 Route Blue를 쓰지 않는다. 전부 흑백 + 회색 단계.
- 그림자: 카드·패널·표에는 없음. 정렬 bottom-sheet(프레임에 안 그림)만 허용.
- 숫자는 모두 고정폭 숫자. 자간 0, Pretendard 300/400/600/700만.
- 준비 중 대학의 점수 자리에 "0", "—", 회색 숫자 같은 자리 표시용 숫자를 넣지 않는다. 배지와 안내 한 줄만 둔다.
