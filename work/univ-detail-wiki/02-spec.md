## 1. 시안 데이터 (가상)

대학·학과 이름은 실제, 전형 내용·쪽수·검수일·컷은 모두 시안용 예시예요(실제 시행계획 아님). 컷 값은 될각 v2와 같아요. 데이터 기준일 2026-11-18, 위키 검수일 2026-11-16, 입결 검수일 2026-11-12.

## 4. 규칙 (시안 숫자의 근거)

- 위키 섹션: 관리자 검수가 끝난 공식 문서 요약만 공개. 검수 전 = 섹션 제목 + "준비 중" 배지만(D4). 섹션마다 따로 판단해요.

- 새 환산·보간·가중치는 없어요. 공개된 9등급 컷끼리 뺄셈만 해요.

## 9. design.md 수정 제안 (만들지 않고 제안만)

1. **섹션 앵커 탭(새 변형 제안, 이름 예: sub-nav variant=anchor).** 긴 상세 화면에서 섹션으로 이동하는 고정 탭. 모양은 sub-nav와 같게: 높이 44, {colors.canvas} 바탕 + 아래 1px {colors.hairline}, 탭 {typography.link}, 선택 = {colors.ink} SemiBold + 아래 2px {colors.accent} 막대, 나머지 {colors.text-muted}, 넘치면 가로 스크롤(오른쪽 여백 0), 모서리 0, 그림자 없음. 다른 점: ① 상세 화면에 허용(모바일 `app-bar` 바로 아래, PC `page-header` 아래에 붙어 고정) ② 탭 = 섹션 제목과 같은 이름(이 화면: 개요 · 특이점 · 반영 방법 · 수능 최저 · 전형요소 · 비슷한 대학) ③ 누르면 해당 섹션 제목이 탭 아래에 오도록 스크롤, 스크롤하면 화면 위쪽에 걸린 섹션의 탭이 선택. 승인되면 D1을 바꿔 이 화면에 넣어요.
2. **AI 요약 표시 규칙.** design.md는 "AI가 만든 모든 블록 머리에 `ai-label`"이라고 하지만, 오너 결정은 검수된 공식 문서 요약에 "공식 문서 요약 · 검수일 YYYY-MM-DD" 라벨이에요. 이 설계는 오너 결정대로 `data-status-badge`를 썼어요. design.md `ai-label` 절에 "관리자 검수 뒤 공개하는 공식 문서 요약은 `data-status-badge` '공식 문서 요약 · 검수일 YYYY-MM-DD'로 대신하고, 검수 전에는 '준비 중'만 보인다"를 더하는 안을 제안해요.
3. **Responsive Strategy 행 추가.** 대학 상세 — 모바일 "요약 → 기본 정보 → 올해 특이점 → 바뀐 점 → 전형 목록 → 반영 방법(접이식) → 수능 최저 → 전형요소 → 입결이 비슷한 대학(카드 + 근거 아코디언)", PC "같은 순서 · 위키 섹션은 data-table · 오른쪽 전형 미리보기 패널".
4. **rules/design-rules.json.** screens에 "대학 상세 위키": "univ-detail-wiki"(또는 univ-detail에 합치기), requires_trace_accordion · requires_disclaimer_note에 추가. 지금은 등록 전이라 G2가 필수 컴포넌트를 검사하지 않지만 이 설계서는 둘 다 넣었어요.
