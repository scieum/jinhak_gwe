# 후속 작업 2 → 3 → 4 → 5

사용자 지시대로 각 단계 검증 후 다음 단계로 진행했다. 추가 조사 우선순위 질문에 사용자가 “ㄱㄱ”로 답해 가천대·강원권부터 요약을 보강했다. 원격 공개 배포·커밋·푸시는 이번 작업에 포함하지 않았다.

## 2. 전형계획 요약

- 2028학년도 218개 캠퍼스·194개 대학명 목록은 유지. 요약은 8개 → 22개 전형, 요약 있는 캠퍼스 항목은 8개.
- 가천대 4개, 강원대 춘천 4개·삼척/도계 3개, 가톨릭관동대 3개 추가. 한림대 기존 3개 보강.
- 새로 보강한 17개 전형에는 지원 자격·방법·수능최저·면접별 PDF 쪽수와 링크를 제공한다. 나머지 기존 5개 요약은 종전 근거를 유지한다.
- 강원대 본교=춘천, 제2캠퍼스=삼척/도계라는 해당 문서 범위를 요약에 명시했다. 강릉·원주에 다른 캠퍼스의 규칙을 적용하지 않는다.
- 시행계획 단계의 검수 전 참고자료다. 학생 성적·수능최저·지원 자격의 자동 판정에 연결하지 않는다.
- 한라대 HWP는 요약 미완료. 모든 대학·전형 구조화 완료가 아니다.

## 3. 비교 → 지원 준비 → 수시로

- 비교표의 각 학과 열에 ‘지원 준비에 추가’를 제공한다.
- 과거 입결 학년도와 실제 지원 학년도를 구분해서 안내한다. 학과는 정확히 전달하고 과거 모집인원·최저·일정을 복사하지 않는다.
- 체크리스트 → `/susiro?plan=...` → 전형 요약 표시 → 사용자가 A~E안과 추가 버튼을 선택한다. 화면을 열기만 해서는 카드를 넣지 않는다.
- 학년도 혼합 추가, 중복, 6회 제한, 삭제된 전형을 저장 트랜잭션에서 검사한다. 기존 준비 기록·관심 목록은 보존한다.

## 4. 입시 일정

- `/calendar` 및 수시 전략 메뉴에 연결. 체크리스트에서도 해당 전형 일정으로 이동한다.
- Figma [calendar/desktop 129:85931](https://www.figma.com/design/AqkVdYZ4hvPYuAlewoBs4W?node-id=129-85931)의 월 제목·오늘·보기 전환·회색 요일 헤더·날짜 셀·다가오는 일정 행·내보내기 구조를 기존 CSS 토큰과 컴포넌트로 구현했다. 실제 일정이 담긴 셀은 44px 터치 영역 이상을 확보했다.
- 달력은 저장된 체크리스트와 수시로의 투영이다. 별도 날짜 사본을 저장하지 않으며 기존 백업 형식을 바꾸지 않는다.
- 같은 지원 기록·고사 종류·날짜가 여러 안에 있으면 한 번 표시하고 A~E 이름을 정렬한다. 날짜가 다르면 각각 남긴다.
- 월간/목록, 전형·종류·완료 필터, 날짜 선택, 상세·수정 화면 이동, 한국 시간 마감·D-day, 날짜 미정 목록.
- ICS는 이번 달 필터 결과만 내보낸다. 날짜 미정 제외, 시각 있는 마감은 UTC 변환, 고사는 종일 일정·배타적 종료 날짜 사용, 한글 UTF-8 75바이트 줄 접기와 특수문자 이스케이프 적용.
- 공식 일정 자동 수집·자동 알림·외부 캘린더 자동 동기화는 하지 않는다. `.ics` 수정본을 다시 가져올 때 외부 달력의 이전 일정 처리 방식은 해당 서비스에 따른다.

## 5. 배포 자료

- Git 제외된 배치표·대학 로고가 새 환경에서 누락되는 점을 확인했다. Git 제외 정책은 유지한다.
- `app/tools/deployment_data.py`: 로컬 폴더 또는 실제 HTTP 응답의 색인·전체 참조 파일·해시·바이트·행 수·입결/배치표 원본 일치·로고 매핑 검사. JSON을 HTML로 대신 반환하는 경우 실패한다.
- 현재 통과 대상: 430개 파일, 75,181,588바이트. 입결 226곳·132,261행, 배치표 3개 학년도, 전형계획 218캠퍼스, 고유 로고 파일 196개.
- `npm run data:bundle -- --archive ...`: 런타임 참조 파일과 무결성 목록만 ZIP으로 만든다. 개인 학생 기록·환경변수·PDF/HWP 원본은 포함하지 않는다.
- `npm run data:restore -- --archive ...`: 임시 폴더에서 전체 검증 후 복원. 경로 이탈·중복 항목·손상·미참조 파일 차단.
- `npm run build:deploy`: 빌드 전 public, 빌드 후 dist 검사. 일반 build는 코드 빌드이며 배포 자료 검사를 대신하지 않는다.
- 로컬 비공개 산출물: `outputs/runtime-data-2026-11-21.zip`(16,715,125바이트). 별도 빈 폴더 `outputs/runtime-restore-2026-11-21` 복원 성공.
- 원격 업로드·공개 배포는 수행하지 않았다. 운영 주소 검사도 별도 남아 있다. 주소가 확정되면 `python tools/deployment_data.py check --url https://실제주소`를 실행한다.

## 검증

- 전체 앱: 44개 파일·402개 테스트 통과. 이후 로컬 근거 파일이 없는 환경의 테스트 처리를 조정하고 관련 16개 테스트 재검사 통과.
- 배포 도구: 정상 왕복·누락·해시 손상·HTML 응답·다른 데이터 버전·ZIP 경로 이탈 테스트 5개 통과.
- `build:deploy`: TypeScript·Vite 프로덕션 빌드 및 public/dist 전수 검사 통과. 기존 큰 청크 경고는 남아 있다.
- 로컬 Vite preview(`127.0.0.1:4183`)의 실제 HTTP 응답 430개도 전수 검사 통과. 이 검사는 원격 운영 서버 검사를 대신하지 않는다.
- ICS URL을 정규화해 줄바꿈이 새 속성으로 출력되지 않도록 보강한 뒤 일정 테스트 6개·배포 도구 5개 재검사 통과.
- 실제 Edge: 전형계획 5개 상세 × 1440/390/320 = 15개 화면, 비교 → 지원 학년도 2029 확인 → 정확한 학과 수시로 추가·새로고침, 일정 3개 너비·상세 Escape·중복 제거·ICS 다운로드·새로고침 확인.
- 스크립트·스크린샷은 `outputs/interest-comparison/check-{plans,prepare,calendar}.cjs`와 같은 폴더에 저장했다. 실제 사용자 브라우저 프로필은 사용하지 않았다.
