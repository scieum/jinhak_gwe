# 수시 입결 — 검색 조건과 조회 결과 영역 분리 시안

## 적용 상태

2026-11-20 사용자 승인: “시안 좋아 이렇게 다른 쪽도 전체 검수하고 적용하자.” 승인된 시안을 앱에 적용했고, 공통 화면과 학생·교사·관리자 화면 검수 결과는 [구현·검수 기록](workspace-layout-review-2026-11-20.md)에 정리했다. 아래는 시안 제작 당시의 기록이다.

## 사용자 요청

현재 앱의 제목·탭·안내문·검색 필터와 데이터 표 사이의 구분이 약하다. 앱 CSS를 바로 수정하기보다 피그마 시안부터 재구성한다.

## 변경 방향

1. PC 상단바는 경로·모드 전환을 맡고, 본문의 큰 페이지 제목은 한 번만 표시한다.
2. 연한 회색 본문 바탕 위에 흰 검색 패널과 흰 결과 패널을 둔다. 1px 테두리와 패널 사이 24px 여백으로 역할을 나눈다. 추가 그림자·새 색·둥근 모서리는 사용하지 않는다.
3. 검색 패널에 자료 탭과 대학·학년도·모집시기·전형 유형을 묶는다. 대학 검색 입력과 선택을 하나의 검색 가능한 선택 필드로 구성하는 시안이다.
4. 결과 패널에는 선택 대학명·결과 건수·검수 상태·전형/모집단위 검색을 둔다. 그 아래 표를 연결하여 검색 결과의 소속이 분명하게 보이게 한다.
5. 큰 안내 배너는 결과 머리의 짧은 참고자료 안내로 정리한다. 성적 판정에 사용하지 않는다는 설명을 유지한다.
6. 모바일에는 대학 선택과 현재 조건 요약을 우선 표시한다. 상세 조건은 별도 시트로 옮기고, 첫 화면에서 모집단위와 50%·70% 컷이 함께 보이게 한다. 지표를 교과등급으로 표시하며 다른 지표가 섞일 때의 그룹 표시 정책은 구현 단계에서 유지해야 한다.
7. 모바일 행의 축약 전형명은 상세 화면에서 전체 명칭을 제공해야 한다. 표에 없는 값은 ‘—’로 유지한다.

## 재사용 및 검증

- 기존 디자인 시스템의 사이드바·앱바·하단 탭·자료 탭·입력·버튼·상태 배지·표 셀·시트를 사용했다. 색·간격 변수와 IBM Plex Sans KR 텍스트 스타일을 연결했다.
- 기존 표 행의 내부 열 너비가 인스턴스에서 변경되지 않아 해당 행 컴포넌트를 화면용으로 복제했다. PC/모바일의 머리·본문 네 가지는 시안 섹션 아래에 두고, 화면에는 그 인스턴스를 배치했다. 기존 공통 컴포넌트는 수정하지 않았다.
- PC와 모바일의 완성 스크린샷을 확인했다. 표의 글자 중간 줄바꿈과 모바일 70% 컷의 화면 밖 넘침을 수정했다. 상세 조건 시트의 중복 버튼도 정리하고 최종 화면을 확인했다.
- 모바일 조건 버튼 → 상세 조건 프레임, 닫기/결과 보기 → 모바일 기본 프레임 전환을 연결했다. 필터값 변경·초기화·실제 데이터 검색 전체를 구현한 프로토타입은 아니다.
- 표 예시는 기존 가야대학교 수집 자료의 일부 행을 사용했다. 수집본의 ‘믈리치료학과’ 표기도 임의 정정하지 않았다. 실제 제품 데이터 검수 완료를 의미하지 않는다.

## 후속 구현 시 확인

- 큰 제목 중복을 없애되 다른 화면의 AppShell 제목 정책에 영향을 주지 않도록 범위를 정한다.
- 검색 가능한 대학 선택, 현재 대학 변경, 학년도/모집시기/유형 필터의 기존 동작을 보존한다.
- 참고자료·검수 완료·관심 전형의 의미를 유지하고, 참고 입결을 성적 판정에 연결하지 않는다.
- 모바일 상세에서 전형 전체 이름·지표·출처·원문 값을 확인하도록 한다. 같은 화면에서 서로 다른 지표의 값을 동일한 컷처럼 보이지 않게 한다.
- 현재 시안은 검토용이며 앱 반영·추가 커밋·푸시는 수행하지 않았다.
