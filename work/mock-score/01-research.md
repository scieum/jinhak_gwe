대상: 학생이 모의고사·수능 직후 영역별 원점수(또는 답안)를 입력 → 예상 등급(관리자가 등록한 예상 등급컷 기준, PRD 6-9) → 수시 카드별 수능최저 충족 현황 → 교사에게 파일·QR로 제출.

## 반영 포인트

- P1: 영역별 원점수 입력은 숫자만 받는 text-input 1칸 + 단위("점")를 붙여 표시하고, 입력 방식(원점수 / 답안)은 segmented-control 2단으로 전환한다. 모바일은 숫자 키패드를 띄우고, 값이 비면 다음 버튼은 비활성으로 둔다. [근거: L1, L2, L3]
- P2: 영역 전환(국어·수학·영어·한국사·탐구1·탐구2)은 화면 상단 segmented-control로 두고, 하단에 고정 요약 줄("6개 영역 중 4개 입력")과 비활성/활성 버튼을 둔다. 입력이 하나도 없으면 빈 상태 안내를 보여준다. [근거: L4, L5, L6]
- P3: 결과 카드는 추정값 앞에 "약"을 붙이고 단일 숫자 대신 범위로 보여준다(예: 예상 등급 "약 2~3등급"). 학생이 입력한 원점수(실제 값)와 추정값을 분리하고, 추정 쪽에 "추정" 표시를 붙인다. [근거: L7, L8]
- P4: 추정값 바로 아래 disclaimer-note로 "가채점 기준 추정이며, 등급컷 기준일·버전에 따라 달라질 수 있어요. 성적 통지표가 최종 기준"을 둔다. 변동 폭 안내를 숫자 근처에 두는 L8 방식을 따른다. [근거: L8, L10]
- P5: 입력 완료 요약은 data-table 하나(행 = 영역, 열 = 원점수 / 예상 등급 범위 / 기준 컷 버전)로 만들고, 숫자 열은 오른쪽 정렬, 헤더 행은 구분 배경을 쓴다. [근거: L11, L12]
- P6: 계산 근거는 trace-accordion으로 접어 둔다. 펼치면 "등급컷 출처·버전(cut_table_version)·기준일 → 내 원점수가 걸친 컷 구간" 순서로 보여준다. 출처별 값을 나란히 보여 주고 근거 리포트로 들어가는 진입 행을 두는 방식을 참고한다. [근거: L9, L10]
- P7: "교사에게 보내기" 전에 확인 모달을 띄운다. 무엇을 보내는지(시험명·영역 수·별칭) 요약하고, 보낼 곳(파일 / QR)과 "서버에 저장되지 않고 이 기기에서 파일·QR로만 전달돼요"를 한 문장으로 알린다. 버튼은 취소 / 보내기 2개. [근거: L13, L17, L18]
- P8: 제출 뒤에는 토스트로 결과를 알린다. 제목 한 줄("가채점 파일을 만들었어요")과 보조 문구 한 줄("이 기기에만 저장돼요")로 쓰고, 화면은 그대로 유지한다. [근거: L14, L15, L16]
- P9 (NEVER-2): L8의 "마감할 가능성이 높아요" 같은 가능성 표현은 가져오지 않는다. 수능최저는 "충족 / 근접 / 미충족 / 자료 부족" 현황 라벨(색 + 아이콘 + 이름)로만 쓰고, "합격 가능·확률·보장" 표현은 쓰지 않는다. [근거: L8]

## 주의 (S2에 넘길 것)

- 표점·백분위: PRD 6-9와 MockScore 모델(areas: {raw, est_grade}, cut_table_version)에는 예상 등급만 있다. 표준점수·백분위 추정 규칙은 PRD에 없으므로 검수된 규칙이 생기기 전에는 계산값을 보여주지 않는다(NEVER-1). 칸을 둔다면 "준비 중"으로 표시한다.
- OMR·답안 그리드: uibowl에서 OMR 형태 레퍼런스는 찾지 못했다(검색어 "답안 입력" 0건). 가장 가까운 것은 L2(객관식/주관식 입력 토글)다. 답안 입력은 2차 범위로 두고, 1차는 원점수 입력으로 가는 편이 안전하다.
- 컴포넌트 이름은 design.md에 있는 것(text-input, segmented-control, data-table, disclaimer-note, trace-accordion)만 쓴다. 모달·토스트가 design.md에 없으면 S2에서 "design.md 수정 제안"으로 멈춘다.
