## 공통 원칙

- 관리자 화면은 PC 중심이에요. 모바일은 조회와 승인·반려만 해요(편집 없음).
- 바탕은 흰 캔버스, 구조는 옅은 회색 단계와 1px 선. 모든 모서리 0. 그림자는 `modal`·`bottom-sheet`·`toast`에만.
- 검수 상태 배지(결정 사항):
  - 작성 중 · 검수 대기 · 반려 = 흑백 `data-status-badge`({colors.canvas-soft} + {colors.text-muted}, {typography.label}).
  - 검수 완료 = 안정 색 쌍(#137a3f 글자 / #e7f5ec 채움) + ● + 이름 "검수 완료". 모양은 `judge-badge`의 안정 쌍을 그대로 써요(design.md "완료·검수 완료는 안정 색 쌍"). 수능 최저 판정 배지처럼 색 쌍만 빌려 쓰는 경우예요.
  - 상태 이름과 PRD 값 연결: 작성 중 = draft, 검수 대기 = testing(테스트 통과 후 요청됨), 검수 완료 = verified, 반려 = draft로 돌아가면서 반려 사유가 붙은 상태.
- 테스트 결과 배지: 통과 = 흑백 `data-status-badge` "통과", 불통과 = 위험 쌍(#b8232a / #fce9ea) ■ + "불통과"(입력 오류 = 위험 쌍 규칙). 색만으로 전하지 않아요.
- 변경 전·후 비교 = `data-table` 3열(항목 / 현재 공개 버전 / 이번 수정안). 바뀐 값만 Bold 700. 증감 색(빨강·파랑)은 쓰지 않아요(전년 대비 숫자 전용이라서).
- 버전 기록 = `counsel-timeline` 재사용(마디 = 버전, 회색 시스템 줄 = 변경 로그).
- NEVER-1을 화면 문구로 드러내요: 편집기·검수 화면 머리에 Level 1 띠 "검수 완료 전 수정안은 학생 화면에서 계산·공개하지 않아요", 목록·패널 맨 아래 `disclaimer-note`.
- 2인 검수 강제: 작성자 본인 계정에서는 승인·반려 버튼을 아예 그리지 않아요(비활성 아님, 숨김). 대신 "내가 작성한 규칙이에요. 다른 관리자가 검수해요." 한 줄.
- Route Blue는 선택 상태에만 써요: 선택된 `sidebar-item`, sub-nav 선택 탭 막대, `segmented-control-active`, 켜진 `filter-chip`, 선택된 표 행·타임라인 마디, `tab-bar-pill` 선택 아이콘, 링크. 이 화면에는 Route Blue 핵심 숫자를 두지 않아요. 배지·버튼 채움에는 쓰지 않아요.
- 주요 버튼(`button-primary`)은 화면마다 하나. 모달·시트가 떠 있으면 그 안의 버튼 하나만 주요 버튼이에요.
- 숫자(점수, 버전, 날짜, 테스트 수)는 모두 고정폭 숫자. 이름·셀은 한 줄 우선(폭을 다시 나눠서 맞추고, 그래도 넘치면 단어 사이에서만 줄바꿈).
- 사람 이름 대신 "관리자 A · 관리자 B · 관리자 C"로 써요. 대학은 가상 대학이라 로고 대신 `univ-monogram`.
- 문구는 해요체. 입시 결과를 점치거나 약속하는 표현은 쓰지 않아요.

## design.md 수정 제안 (새 컴포넌트는 만들지 않았어요)

1. 검수 완료 배지: `data-status-badge`는 "판정 색을 쓰지 않습니다"인데 Semantic에는 "완료·검수 완료는 안정 색 쌍"이라 겹쳐요. 이 문서는 `judge-badge` 안정 쌍 ● "검수 완료"로 정했어요. judge-badge 절에 "검수 완료 배지(관리자): 안정 쌍 ● + '검수 완료'" 한 줄을 넣어 주세요.
2. 테스트 불통과 배지: 위험 쌍 ■ "불통과"를 썼어요(입력 오류 = 위험 쌍 규칙의 확장). 맞는지 한 줄 확인이 필요해요.
3. 비활성 `button-primary` 모양이 정의돼 있지 않아요. 이 문서는 {colors.canvas-soft} 채움 + {colors.text-faint} 글자로 썼어요.
4. 여러 줄 `text-input`(반려 사유, 높이 120)과 표 안 편집 셀(`data-table` 셀 안 `text-input` 높이 32)이 정의돼 있지 않아요. 변형으로 적어 주세요.
5. `univ-card` 관리자 변형(하트·"수시로에 담기" 없음, 배지 자리에 상태 배지)을 허용한다고 적어 주세요.
6. 패치 4(apply4.py)의 관리자 내비: PC 대분류는 있지만 모바일 탭바 구성이 없어요. 이 문서는 "규칙 관리 · 더보기" 두 탭으로 썼어요. 관리자 상단 바에 `mode-switch`·잠금 버튼을 두지 않는 것도 적어 주세요.
7. 모바일 밀도(좌우 20, 섹션 32)는 design.md Grid의 모바일 좌우 16과 달라요. 2026-11-18 밀도 규칙으로 design.md에 반영해 주세요.
