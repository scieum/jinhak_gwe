## 반영 포인트

- P1: 보기 전환은 segmented-control 두 칸 "한 달 · 목록"만 둔다. 한 달 = 월간 그리드(앱바 아래 "‹ 2027년 11월 ›" 월 이동), 칸에는 일정 이름 대신 잉크 점(ELLIPSE, 최대 3개 + "+n")만 찍고 날짜를 누르면 그날 목록이 아래(모바일) / 오른쪽 패널(PC)에 뜬다. 목록 = 날짜 머리("11.21 토 · D-3") 아래 행 목록, 일정 없는 날은 건너뛰고 "오늘"에는 꼬리표. 주간·3일·하루 보기는 만들지 않는다(입시 일정은 하루 단위라 필요 없음). [근거: L1, L2, L4, L8, L11]
- P2: 일정 유형 필터는 filter-chip 가로 줄(전체 · 원서 · 서류 · 면접 · 논술 · 실기 · 발표 · 등록 · 수능·모의고사). 모바일은 sub-nav 아래 가로 스크롤 한 줄, PC는 오른쪽 패널 머리. 출처 필터(수시로 6장 / 관심 대학 / 공통 일정)는 칩 줄을 늘리지 말고 bottom-sheet(모바일) / modal(PC) 안 체크 목록으로 둔다. L1의 하단 떠 있는 세그먼트는 tab-bar-pill과 겹치므로 가져오지 않는다. [근거: L1, L2, L3, L8]
- P3: 판정 색과 일정 유형은 섞지 않는다 — 일정 유형은 색이 아니라 "텍스트 꼬리표"(흑백 알약: canvas-soft + ink, 예 "면접", "논술")로만 구분한다. 판정 색은 design.md Don't("판정 색을 카테고리 구분에 쓰지 마세요")에 걸리고, Route Blue는 "선택됨·여기예요" 전용이라 유형 색으로 못 쓴다. 따라서 새 색이 필요 없다. Route Blue는 오늘 날짜 표시·선택한 날짜·선택된 filter-chip·D-day 핵심 숫자 1개에만 쓴다. judge-badge는 그리드·목록에 넣지 않고, 일정 상세(수시로 카드에서 온 일정)에서만 색 + 아이콘 + 이름으로 보여준다. [근거: L1, L2, L11]

L3의 "읽기 전용" 출처 표시처럼 관리자 데이터는 학생이 고칠 수 없다고 상세에 캡션으로 둔다. [근거: L3, L9]

## design.md 수정 제안 (S2 전에 확인 필요)

- 컴포넌트 목록에 캘린더 부품이 없다: 월간 그리드(`calendar-month` — 날짜 칸, 오늘/선택 표시, 점), 목록 행(`agenda-row` — 날짜 머리 + 유형 꼬리표 + 대학·전형), 다가오는 일정 카드(`dday-card`), 유형 꼬리표(`event-type-tag`, 흑백 알약). G2가 "design.md에 없는 컴포넌트 이름 = 0"을 보므로, 이름을 정해 design.md·rules `components`에 올리거나 기존 이름으로만 설계하도록 정해 주어야 한다.
- 새 색은 필요 없다(P3: 유형 = 흑백 텍스트 꼬리표). 겹침 표시는 warning-callout(소신 쌍) 재사용.
- App Shell 대분류-소분류 목록에 "수시 전략 › 입시 일정", "수합·집계 › 고사 일정" 추가가 필요하다(P10).
- rules/design-rules.json `screens`에 "입시 캘린더": "calendar"가 없다. 그리고 이 화면에 환산·판정 숫자는 없지만 일정이 공식 자료 기준이므로 `requires_disclaimer_note`에 넣을지 정해 주어야 한다.

## 가져오지 않는 것

- 레퍼런스의 일정 색 구분(L3·L8의 캘린더별 색 체크, L4의 분홍·보라 막대, L2의 하늘색 강조): 유형은 흑백 꼬리표로만 나눈다.
- L1의 하단 떠 있는 필터 세그먼트(tab-bar-pill과 겹침), 둥근 모서리 전부(모서리 0), L10의 캐릭터·그라데이션 배경.
- 주·3일·하루 보기(L8), 구글 캘린더 계정 동기화(L5): 범위 밖, 서버 없음.
