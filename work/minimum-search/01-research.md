## 0. 이 화면이 하는 일 (다른 화면과 나눔)

| 화면 | 누구 | 무엇을 기준으로 | 결과 |
|---|---|---|---|
| minimum-board | 교사 | 반 학생 × 각자 1순위 목표 | 학생별 판정 표, 상담 명단 |
| mock-score | 학생 | 가채점 등급 × 내 수시로 카드(최대 6장) | 카드별 충족 현황 |
| **minimum-search** | 학생 | 내 모의고사 등급 × **검수된 전체 수능 최저 전형** | 충족·근접·미충족·자료 부족으로 묶은 전형 목록 + 영역별 1등급 what-if 개수 차이 |

- 데이터: 관리자 검수 `csat_minimum`만 써요. 검수 전 기준은 목록에 넣지 않고 "자료 부족" 개수에만 셀지 S2에서 정해요(NEVER-1).
- 판정 = 충족 ● / 근접 ◐ / 미충족 ■ / 자료 부족(이름만), `judge-badge` 색 쌍 재사용(minimum-board·mock-score와 같은 정의). 근접 = 한 영역만 1등급 좋아지면 기준 안.
- 문구: "충족 현황", "1등급 오르면 충족 전형 +n개". 앞날을 단정하거나 될지 안 될지를 숫자로 말하는 표현은 쓰지 않아요(NEVER-2).

## 2. 반영 포인트

- P1: 조건을 바꾸면 결과 개수가 같은 자리에서 바로 바뀌게 해요. 칩 줄 바로 아래 "충족 n개 · 근접 n개" 요약 줄, 모바일 조건 시트의 주요 버튼은 "충족 전형 n개 보기"처럼 개수를 담아요 [근거: L1, L2, L3]
- P2: what-if 조절은 영역별 −/+ 스텝퍼(1등급 단위)로 해요. 등급은 1~9 정수라 연속 슬라이더(L1·L11)보다 스텝퍼가 맞고, 값이 바뀌면 바로 아래 결과 숫자가 다시 계산되는 구조를 따라요. 위아래 끝(1등급·9등급)에서는 해당 버튼 비활성 [근거: L6, L7, L1]
- P3: 결과 요약은 판정별 개수 타일(충족 / 근접 / 미충족 / 자료 부족) 묶음으로 해요(`stat-tile`). 타일 숫자는 잉크색, 판정 색은 목록의 `judge-badge`에만 둬요(minimum-board와 같은 규칙). 비율 막대는 넣지 않아요 — 판정 색 막대가 되기 쉬워서 [근거: L9, L3]
- P4: what-if 결과는 "지금 → 국어 1등급 오르면" 전후 두 칸 비교로 보여 줘요. 영역마다 한 행(국·수·영·탐), 열 = 지금 충족 수 | 바꾼 뒤 충족 수 | 차이 "+n개". 차이는 부호와 숫자로만, 색으로 좋다/나쁘다 표시하지 않아요(`data-table`) [근거: L8, L1]
- P5: 목록 필터는 판정별 칩(`filter-chip` "충족 24" · "근접 9" …)과 계열·지역 칩 한 줄. 모바일에서 조건이 많으면 바텀시트로 열고 "초기화" + 취소/적용을 둬요. "~만 보기" 문구 방식을 따라요 [근거: L4, L2, L3]
- P6: 판정 기준 범례를 결과 목록 위에 한 줄로 먼저 보여 줘요: "충족 ● 기준 안 · 근접 ◐ 한 영역 1등급이면 기준 안 · 미충족 ■ · 자료 부족" — 색 + 아이콘 + 이름을 범례에서도 같이 [근거: L10]
- P7: 기준 성적 고르기(어느 모의고사·가채점)를 맨 위 `segmented-control`로 먼저 정하게 해요. 조건을 하나씩 먼저 정하고 결과를 보는 순서 [근거: L5]
- P8: 근접 전형 행에는 "기준 합 7 · 내 합 8"처럼 기준 대비 내 값을 숫자로 적고, 그래프가 필요하면 범위 막대 위 점 하나(내 위치)만 둬요. 이 점이 Route Blue를 쓰는 유일한 자리 후보예요(승인 체크 "Route Blue는 내 위치에만") [근거: L11, L10]
- P9: 목록에서 전형을 골라 "관심 담기/수시로에 담기"로 넘기는 선택 수 카운터("2개 담음")는 두되, 비교를 강제하는 최소 개수 제한은 두지 않아요 [근거: L12]

## 3. 내비 위치 제안

**1안(추천) 대분류 "대학 찾기" › 소분류 "최저로 찾기"**
- 결과물이 "전형 목록"이고, 다음 행동이 관심 담기·수시로 담기라서 대학 찾기 흐름에 맞아요.
- "성적" 대분류는 소분류가 이미 5개(성적 입력 · 성적 추이 · 5 to 9 · 대학별 환산 · 가채점)라 모바일 sub-nav가 더 길어져요.
- 진입 링크는 성적 쪽에도 둬요: 가채점(mock-score) 최저 현황 섹션 아래 "최저 맞는 전형 더 찾기 ›", 성적 입력 완료 뒤 안내.

2안 대분류 "성적" › 소분류 "최저 찾기"
- 입력(내 등급)과 가까워 이해는 쉬우나, 성적 대분류가 "내 숫자 보기"에서 "대학 고르기"까지 넓어져요.

S2 확인 필요: "대학 찾기" 대분류의 현재 소분류 목록(work/_pending/apply4.py 기준)을 보고 이름 겹침을 확인해 주세요. 이번 S1에서는 apply4.py를 열어 보지 않았어요.

## 4. S2 주의 · 미결

1. what-if 범위: 한 번에 한 영역만 1등급(근접 정의와 같게) 할지, 여러 영역 동시 조절을 허용할지. 동시 조절은 조합이 많아 "이렇게 하면 된다"로 읽힐 위험이 커져서 1차는 한 영역씩만 권해요.
2. 판정에 쓸 등급: 가채점은 범위의 불리한 쪽(mock-score 규칙), 실채점 모의고사는 그 등급 그대로.
3. 검수 전 기준(교사 입력 등)은 목록 제외 vs "자료 부족"에 포함 중 결정. 이 화면은 학생용이라 제외 쪽을 권해요.
4. 근거 표시: 행을 누르면 `trace-accordion`(기준 → 고른 영역 → 합 → 판정)과 `disclaimer-note`("대학 모집요강이 최종 기준이에요 · 데이터 기준일")를 둬요.
5. uibowl에서 "조건 하나 바꾸면 충족 개수 +n" 그대로인 화면은 못 찾았어요(검색 `시뮬레이션`·`조건 충족` 0건). P2·P4는 스텝퍼 즉시 재계산(L6·L7) + 결과 수 버튼(L1) + 비교 표(L8)를 조합한 설계예요.
6. 체크리스트형 "조건 충족 체크"는 집지켜(L5) 흐름만 확보했어요. 화면 안 체크 목록 사례가 더 필요하면 `조회하기 + 체크박스` 다음 페이지(유료)가 필요해요.
