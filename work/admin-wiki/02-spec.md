표시 규칙: "확정(앱)" = 지금 앱에 있는 기능 · 문구를 그대로 그려요. "확정(기본안)" = 앱 기능은 그대로이고 모양 · 배치만 design.md 규칙에 맞춰 planner가 정한 것이에요(앱 코드도 따라 바꿔야 하는 것은 9-참고에 적었어요). "확정(새 기능)" = 앱에 없던 새 기능이에요. 처음엔 [확인]으로 올렸고 2026-11-23 사용자 결정(채팅)으로 모두 넣기로 확정했어요 — 앱 코드에도 새로 넣어야 해요(9-참고).

## 4. 규칙 · 데이터

- 상태 = 승인 수: 0개 검수 대기, 1개 1인 승인, 2개 검수 완료. 같은 검수자는 한 번만 승인해요.
- 요약을 고쳐 저장하면 승인이 모두 지워지고 검수 대기로 돌아가요. 공개 파일에는 다시 검수가 끝날 때까지 **이전에 공개된 내용이 그대로 남아요**(내보내기는 검수 완료 섹션만 덮어써요).
- 승인 전 확인: 요약 1개 이상, 요약마다 내용 · 출처 이름 · https 출처 주소, 금지 표현 없음. 하나라도 걸리면 승인 버튼 비활성.
- 공개 파일 내보내기 = 검수 완료이면서 고칠 곳이 없는 섹션만 univ-wiki.json에 넣어요. 0개면 오류 줄(1440-export-error). 버튼은 검수 완료 0개면 비활성이지만, 가져온 기록에 고칠 곳이 남은 검수 완료 섹션만 있으면 버튼이 켜져 있어도 이 오류가 나요.
- 검수 기록 가져오기: 내용이 같은 섹션은 승인을 합치고, 내용이 다른 섹션은 확인 창(C1)에서 바꿀지 물어요.
- 공개 쪽 표시는 design.md ai-label 예외 규칙(섹션 머리 "공식 문서 요약 · 검수일" 배지 + 블록마다 출처)을 따라요. 이 화면은 숫자를 계산하지 않아서 NEVER-1(검수 안 된 환산 규칙)과 닿는 숫자가 없어요.

## 7. 접근성

- 표: 열 머리글 연결, 대학 칸은 버튼("경희대학교 수능 최저 요약 열기, 검수 완료"). Tab으로 행 이동, Enter로 편집기.
- 상태 배지는 글자 그대로 읽혀요. 검수 대기 · 1인 승인 · 검수 완료 모두 흑백 이름만(색에 기대지 않음, D4).
- 완료 `toast`는 조용한 알림(status, 보이는 시간은 design.md toast 규칙), 오류 줄은 즉시 알림(alert). 아이콘은 장식(alt 빈값), 문장이 뜻을 전해요.
- 편집기 · 확인 창: 열면 첫 입력칸(확인 창은 제목)으로 포커스, 안에서 Tab 순환, Esc = 닫기, 닫으면 누른 대학 칸으로 포커스가 돌아가요(앱 Modal과 같음). 모달 이름 = "{대학} {섹션} 요약".
- 요약 칸: 400자 제한을 글자 수 캡션으로 보이고 읽어요("128자, 최대 400자"). 오류 칸은 aria-invalid + 오류 캡션 연결. "이 요약 삭제" 접근성 이름 = "2번 요약 삭제".
- 비활성 버튼에는 이유를 옆 글(저장 안 함 띠 · 고칠 곳 박스 · 내 승인 안내)로 보여 줘요. 숨긴 승인 버튼 자리는 내 승인 안내가 대신 읽혀요.
- 숫자(요약 개수 · 글자 수 · 상태 개수) 고정폭. 모바일 누르는 요소 44 이상, PC 표 안 컨트롤 32 이상 · 그 밖 버튼 40 이상. 포커스 2px 잉크 링. 대비 4.5:1.
- 모달 · 시트 240ms, 결과 줄 150ms 페이드, prefers-reduced-motion이면 바로.
