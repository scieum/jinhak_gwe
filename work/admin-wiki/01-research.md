### 0-4. 앱에는 없지만 시안에서 더 그려 볼 후보 (사용자 요청 "안 그린 기능 · 팝업")

구현에 없는 것이라 S2에서 넣을지 정해요. 새 컴포넌트 없이 design.md `modal` · `toast` · `empty-state`로 되는 것만 적었어요.
- C2 "이 요약 삭제" 확인 — 지금은 누르면 바로 지워짐(저장 전이라 닫으면 되돌아감)
- C3 저장하지 않고 닫기 확인 — 지금은 닫기 · Esc가 바로 닫음(고친 내용 사라짐)
- C4 검수 완료 요약을 고쳐 저장할 때 "승인 2개가 지워져요" 확인 — 지금은 캡션 한 줄로만 알림
- C5 공개 파일 내보내기 전 확인(내보낼 섹션 n개 · 대학 목록 미리 보기)
- T1 완료 줄(S-e, S-g)을 `toast`로 — design.md 예시 "상담카드 3개를 불러왔어요"와 같은 성격
- 출처 "원문 보기 ↗" 링크 — 표 · 편집기에서 출처 주소를 바로 열어 보는 링크(지금은 입력칸만 있음)

## 2. 반영 포인트

- P1: 편집기(M1)는 `modal` size=wide로, 머리(대학 · 섹션 · 승인 캡션 · 상태 배지)와 바닥 고정 줄(닫기 · 저장 · 승인)을 두고 요약 목록만 스크롤해요. 바닥 버튼은 보조 2개 + 주요 1개(승인), 조건이 안 되면 비활성으로 그려요. 긴 요약은 textarea + 글자 수(400자) 표시 [근거: L4, L7, L5]
- P2: 상태 프레임은 M1-a~g를 각각 그려요. 특히 "저장 안 함"(M1-c)은 모달 위쪽 또는 바닥 줄 바로 위에 띠 한 줄 "저장하지 않은 내용이 있어요 · 저장하면 승인이 지워져요"로 눈에 띄게, "내가 이미 승인"(M1-e)은 승인 버튼 자리에 notice로 대체 [근거: L11, L1, L3]
- P3: 승인 전 고칠 곳(M1-b)은 두 층으로 보여요: 해당 입력칸 바로 아래 오류 한 줄(`text-input-error`) + 바닥 줄 위 error-note 요약 "승인 전에 고칠 곳 n개". 오류가 남아 있으면 승인 비활성 [근거: L12, L13]
- P4: 목록 표는 `data-table` 그대로, 상태 열을 배지로(대기 · 1인 승인 = `data-status-badge`, 완료 = 판정 색 + 아이콘 + 이름 "● 검수 완료"). 승인자 칸은 이름 · 이름 / "—". 표 위는 검색 1줄 + `segmented-control` 개수 표시 [근거: L8, L10, L9]
- P5: 확인 팝업 C1(가져오기 충돌)은 브라우저 기본 창 대신 `modal` 확인형으로: 제목 "내용이 다른 섹션 n개", 본문에 섹션 목록(대학 · 섹션) 최대 3개 + "외 n개", 경고 한 줄 "이 기기에서 고친 내용은 사라져요", 바닥 "그대로 두기 / 가져온 파일로 바꾸기". 후보 C2~C5도 같은 틀 [근거: L6, L5, L2]
- P6: 빈 상태는 두 가지를 구분해요: 기록 0개(S-a) = `empty-state` 아이콘 + 제목 + 설명 + 버튼 하나("요약 쓰기·고치기"), 필터 결과 0(S-c) = 표 자리에 회색 한 줄만 [근거: L15, L14, L3]
- P7: 완료 · 실패 줄(S-e~S-h)은 완료를 `toast`(예: "검수 기록 12개를 합쳤어요"), 실패를 본문 오류 줄로 나눠 그리는 안을 S2에서 비교해요. 공개 범위 · 출처 규칙은 notice(B2)와 `disclaimer-note`(B8)로 화면에 항상 남겨요 [근거: L11, L8]
