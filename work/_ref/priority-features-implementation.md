# 우선순위 높음 4개 기능 구현

대상: 추가 기능 조사표 N01·N03·N04·N06. 사용자 요청 “우선순위 높음까지 구현하자”에 따라 웹앱에 구현했다. N02(전년·올해 산식 영향 비교)는 앞선 채팅에서 “데이터 확보 후”로 구분한 항목이라 이번 범위에서 제외했다. Figma 원본 수정이나 배포 완료를 뜻하지 않는다.

## 구현 결과

| 기능 | 앱 경로 | 구현한 동작 |
|---|---|---|
| N01 원서·서류 체크리스트 | `/application-checklist` | 대학·전형·학년도·모집단위·자료 링크 등록/수정/삭제. 원서 작성·결제·접수 확인·서류 제출·도착 확인을 독립적으로 관리. 사용자 항목 추가/수정/삭제, 한국 시간 마감, 미정·진행·완료·해당 없음, 확인 시점·메모 |
| N03 지원 자격 확인표 | `/eligibility-check` | 동일 지원 전형별 자격·졸업연도·지역·추천 조건 확인. 기본 확인 항목과 사용자 정의 조건. 확인 필요/충족으로 확인/미충족으로 확인/해당 없음. 근거·자료 링크·문의할 담당자 메모 |
| N04 상담 질문·할 일 | `/counsel-tasks` | 상담 전 질문/상담 후 할 일 구분, 전형 연결/공통 상담, 상담일·기한·메모, 완료/다시 진행, 종류·완료 상태·전형 필터, 기한순 정렬, 삭제 확인 |
| N06 입결 비교 조건 | `/admission-results`, `/doelgak` | 내 환산 기준과 입결 기준을 나란히 표시. 학년도·등급제·지표·70% 컷 여부·만점·반영 교과·학기·산식/버전·출처·검수 확인. 조건 누락/불일치 시 점수 차이·될각 판정 차단 |

학생 홈에서 4개 화면으로 연결했다. 메뉴는 수시 전략의 체크리스트·상담, 대학 찾기의 자격 확인표·수시 입결에 배치했다.

## 사용할 때

1. 체크리스트에서 지원 전형을 추가한다. 운영 전형이 등록되어 있으면 목록에서 선택할 수도 있다.
2. 각 단계에서 ‘수정’을 눌러 상태·기한·자료·메모를 저장한다. 결제 완료가 접수나 서류 도착 완료로 자동 전파되지는 않는다.
3. ‘지원 자격 확인하기’로 이동해 같은 전형의 모집요강을 읽으며 조건을 기록한다. 적용되지 않는 기본 항목은 ‘해당 없음’으로 표시하거나 삭제한다.
4. ‘상담 질문·할 일’로 이동하면 전형 연결을 유지한 채 질문/과제를 작성할 수 있다. 완료한 항목은 완료 필터에서 다시 열 수 있다.
5. 성적 입력 화면의 암호화 백업·복원으로 전체 기록을 옮긴다.

## 저장·복원·삭제

- 기존 학생 IndexedDB를 v1→v2로 마이그레이션한다. 성적·출결 테이블은 유지하고 `applications`, `tasks` 테이블을 추가했다.
- 새 스냅샷의 `planning`에 전형·체크·자격·상담이 포함된다. 기존 AES-GCM 암호화 백업에 함께 담는다. 백업 암호 형식이나 기존 파일을 깨뜨리는 변경은 없다.
- 이전 성적 전용 백업에는 `planning`이 없으므로 성적·출결만 교체하고 준비·상담 기록을 유지한다. 새 백업은 확인 화면에 전형·상담 개수를 표시하고 전체 준비 기록도 교체한다.
- ‘이 기기의 학생 데이터 지우기’는 성적·출결과 새 기록을 전부 지운다. 확인 문구도 범위에 맞게 바꿨다.
- 전형 삭제는 체크리스트·자격 확인을 지우되 연결된 상담 질문·할 일은 보존하고 연결만 해제한다.
- 전형의 학년도·대학·전형명·모집단위가 바뀌면 이전 전형의 확인 상태·기한·근거·메모를 초기화한다. 저장 전에 초기화 안내를 보여준다. 다른 전형은 수정 대신 추가할 수 있다.
- 잘못된 날짜, 중복 ID, 고아 상담 참조, 상태/확인시각 불일치, https가 아닌 링크, URL에 포함된 사용자명/암호를 거부한다. 복원 검증은 기존 데이터 변경 전에 수행한다.
- 성적·준비 기록은 서버로 전송하지 않는다. 학생이 직접 외부 자료 링크를 눌렀을 때만 해당 사이트로 이동한다.

## 데이터와 해석 범위

지원 자격 확인표는 **학생의 확인 기록**이다. 대학의 최종 자격 판정이나 학교장추천 배정을 자동으로 확정하지 않는다. 증빙 원본 업로드는 없다. 체크리스트도 원서접수 사이트와 동기화한 접수 증명이 아니다.

운영용 대학·입결 자료는 기존과 같이 비어 있다. 가상 대학이나 임의의 컷을 실제 데이터로 배포하지 않았다. 전형·체크·자격·상담은 수동 등록으로 사용할 수 있고, 입결 화면은 자료 미등록과 비교 기준을 보여준다.

`cut_basis`가 없는 기존 데이터는 판정할 수 없다. 원등급 평균·추정 환산등급·대학별 점수를 구분하고, 비교할 기준에 학년도와 산식 버전도 일치해야 한다. 역사적 입결을 현재 성적과 비교하려면 동등한 기준으로 사용할 수 있는지 별도 검수된 데이터 정책이 필요하다. 단순히 과거 입결의 연도나 산식 표기를 현재 값으로 고쳐서 차단을 해제하면 안 된다.

환산 구성의 내용이 바뀌면 비교용 산식 지문도 달라지게 했다. 이 지문은 버전 변경 감지용이며 암호학적 보안 해시가 아니다.

## 검증

- 테스트: 12개 파일, 총 159개 통과. 신규 마이그레이션·백업 왕복·잘못된 복원 보존·KST 날짜 경계·독립 체크·자격 상태·상담 완료/재진행·삭제 확인·비교 조건 차단 포함.
- `npm run build` 통과. 기존 ExcelJS와 앱 번들 크기 경고가 남아 있다.
- 실제 Chrome에서 전형 추가→독립 체크 완료→새로고침 복원→자격 근거 저장→상담 완료→새로고침 복원→입결 미등록 상태를 확인했다. 1440px·390px 가로 넘침 없음, 페이지 실행 오류 없음. 테스트 데이터는 별도 임시 브라우저에서만 사용했다.
