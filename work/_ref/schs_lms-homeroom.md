# 참고: scieum/schs_lms — 담임(homeroom) 기능과 학생 성적 화면

출처: 공개 GitHub `scieum/schs_lms`, `apps/web` (Next.js). 조사일 2026-11-18, HEAD 기준.
목적: 진학 내비 화면 설계 참고. 코드가 아니라 "화면에 무엇이 보이고 무엇을 할 수 있는가"만 뽑았다.
실명·시드 데이터는 옮기지 않았다. 코드에서 확인 못 한 내용은 "추정"이라고 적었다.

공통 패턴 (거의 모든 담임 화면에 반복됨)
- 상단 숫자 타일 4개(StatTiles/NumberStrip) → AI 배너 한 줄(AiBanner) → 본문 카드 2단(왼쪽 넓게, 오른쪽 340px).
- AI 배너에는 늘 라벨 `AI` 또는 `자동`이 붙는다. AI가 꺼져 있거나 실패하면 같은 자리에 규칙으로 계산한 문장을 보여 주고 라벨만 `자동`으로 바뀐다.
- AI 결과는 바로 저장하지 않는다. 체크박스로 고르고 문구를 고친 뒤 "확인 후 저장/보내기/담기"를 눌러야 반영된다.
- 결과 카드 아래 회색 작은 글씨로 무엇을 AI에 보냈는지 밝힌다 (예: "가명ID·등급만 AI에 보냈어요 · 저장하지 않아요").
- 빈 상태는 카드 안 가운데 회색 한 줄 ("아직 ~가 없어요"), 오류는 빨간 글씨 한 줄(role=alert).
- PC는 표·5열 카드, 모바일은 목록(아바타 + 이름 + 태그)으로 바뀐다.

## 2. 화면별 상세

### 2-1. 우리 반 홈 (/homeroom)
- 헤더: "N학년 N반", 오른쪽 "학생 기록" 버튼(PC).
- 숫자 타일 4개: 우리 반 N명 / 받은 초안 N건 / **최저 충족 예상 N명**(잠금 시 "상담 필요 N명"으로 대체) / 오늘 야자 N명. 첫 타일에 "받은 초안 확인" 버튼.
- 우리 반 브리핑(AI 배너): 기본 한 줄은 규칙 문장 "먼저 볼 학생 3명 · 최저 근접 2명 · 정정 요청 1건". "먼저 볼 학생" 버튼 → 카드에 학생 3명(이름, 신호 태그 최대 2개, 이유 한 줄, "상담 일정 잡기" 버튼).
  - 규칙(AI 없을 때): 학생별 신호 점수 합이 큰 순. 최저 근접 4점, 최저 미충족 3점, 4주 야자 결석·조퇴 3일 이상 3점/2일 2점, 정정 요청 대기 2점, 새 초안 1점, 최저 자료 부족 1점.
  - AI: 규칙 후보 6명 중 3명과 이유(45자)를 고름. 가명ID·신호 문장만 보냄. 카드 태그 "AI 추천" / "규칙으로 고름".
- 학생 한눈에: 탭 `전체 N` / `최저 미충족 N`(잠금 시 숨김) / `상담 필요 N`. PC 5열 카드(아바타·이름·번호·태그 또는 "초안 n · 상담 n"), 모바일 6명 목록 + "N명 전체 보기".
- 오른쪽: 조각 모으기(이번 주 남긴 조각 수, 조각 적은 학생 칩 6개 → 누르면 그 학생에게 남기기), 받은 생기부 초안(프로그램별 최근 3개, 7일 내면 "새로 도착" 태그), 이번 주 일정(7일 내 프로그램 시작·마감 4개).
- 빈 상태: "아직 등록된 학생이 없어요", "해당하는 학생이 없어요", "아직 받은 초안이 없어요", "이번 주 일정이 없어요", "지금 먼저 챙길 학생이 없어요".

### 2-2. 학생 기록 목록 (/homeroom/students)
- 숫자 타일: 학생 N명 / 이번 학기 상담 N건 / 상담 없음 N명 / 정정 요청 N명.
- 학생 카드 그리드(1~3열): 아바타, 이름, "학번 · 상담 n(또는 상담 없음) · 정정 요청". 누르면 상세.

- 탭: 행발 | 자율·자치 | 진로. 같은 작업 틀(왼쪽 조각 = 누가기록 + 관찰 메모, 가운데 본문, 라이브러리 패널).

### 2-6. 받은 초안 (/homeroom/drafts)
- 숫자 타일: 받은 초안 / 확정 대기 / 받은 학생 / 우리 반.
- 목록 행: "번호 이름" + 영역 태그 + "프로그램명 · MM.DD" + 본문 2줄. 오른쪽 "확정" 버튼 또는 "✓ 조각에 넣음" + "조각 보기 ›". 머리에 "모두 확정 N".
- 확정 = 자율·자치/진로 조각으로 추가(본문에 바로 넣지 않음). 추가만, 중복 안 넣음.
- 빈 상태 "아직 받은 초안이 없어요. 프로그램 선생님이 확정하면 여기로 와요."

### 2-9. 야간 자율학습 (/homeroom/night)
- 반 고르기(ClassPicker), 숫자 타일: 신청 / 출석 / 결석·조퇴 / 승인 대기. "출석 마감하기" 버튼(마감 후 "마감했어요", 주말엔 숨김).
- 출석 체크 카드: 1교시/2교시 탭, 학생 칸 누를 때마다 출석 → 결석 → 조퇴 순환(바로 저장), "모두 출석". 상태: 출석·결석·조퇴·미신청·미확인. 하단 "아직 확인 안 한 학생 N명".
- 승인 대기 카드: 학생·날짜·사유·시간·장소, "반려"/"승인".
- 이번 주 출석률 막대(요일별 %, 오늘 강조).
- 출결 살펴보기(AI 배너): "메시지 만들기" → 학생별 결석 패턴 + 고칠 수 있는 메시지 초안 → 체크 → "확인 후 보내기(N명)" → 학생 야자 화면으로 전달. AI 없으면 "기본 문구".
- 내보내기: "출석 엑셀"(번호·이름·날짜·시간·장소·1교시·2교시).
- 빈 상태: "주말에는 야간 자율학습이 없어요", "대기 중인 신청이 없어요".

### 2-10. 봉사 받은함 (/homeroom/service)
- 숫자 타일: 확인 대기 / 확인함 / 반 총 시간 / 학생.
- AI 배너 "봉사 누적 살펴보기": 규칙 문장 "평균 n시간 · 기록 없는 학생 n명 · 평균 절반 미만 n명 · 7일 넘게 확인 대기 n건". "AI 한 줄" 버튼(가명ID·시간만).
- 확인 대기 행: "번호 이름 · n시간", "기간 · 기관 · 보낸 분", 활동내용 + 길이 칩. 50자(150B) 넘으면 경고 띠 + "줄이기"(AI) → "바꾸고 확인". 확인서 파일 링크, "확인".
- 학생별 누적: 2~6열 칩, 0시간·평균 절반 미만은 빨간 숫자, "대기 n" 태그.

### 2-11. 담임 메뉴 (/homeroom/menu, 모바일)
- 묶음 "담임": 조각 모으기 · 글 짓기 · 받은 초안 · 글 모아 보기.
- 묶음 "우리 반 업무": 학생 기록 · 봉사 받은함 · 성적 업로드 · 수능 최저 · 야간 자율학습. 잠금이면 성적 업로드·수능 최저가 빠진다.

### 2-12. 내 성적 — 학생 (/student/scores)
- 잠금이면 /locked로 이동.
- 헤더 "내 성적", 오른쪽 "목표 대학 설정"(모바일 "목표") 버튼 → 바텀시트: 1~3순위, 각 순위마다 "기준이 있는 대학" 드롭다운(대학 학과 · 기준 요약) 또는 "직접 쓰기"(대학·학과 입력). "대학 더하기", "빼기". 안내 "목록에 없는 대학은 담임 선생님이 기준을 넣으면 판정돼요".
- 숫자 타일(최근 시험): 국어 n등급 / 수학 / 영어 / 탐구 평균 n.n등급.
- 성적 분석(AI 배너): 기본 문장 = 규칙 추이 문장(예: "N개월간 평균 0.5등급 올랐어요. 수학이 가장 많이 올랐어요"). "필요한 등급 보기" → 카드 "필요한 등급과 공부 계획": 목표별 필요 문장(최대 3) + 공부 계획 체크 목록(3~5) → "확인 후 담기".
- 모의고사 추이 카드(TrendCard) + 내신 카드 — 3(c).
- 목표 대학 최저 기준 카드: 목표마다 "대학 학과" + 판정 태그 + "기준 요약 · 이유" + 필요한 것 한 줄. 아래 "N월 모의고사 · 한국사 n등급 · 과목: 6개 공통과목".
- 내 공부 계획 카드(저장한 최신 계획, 날짜).
- 빈 상태: "아직 모의고사 성적이 없어요", "내신 성적이 아직 없어요", "오른쪽 위 '목표 대학 설정'에서 정해 주세요", "기준이 아직 없어요 · 담임 선생님께 알려 주세요".

## 3. 자세히

### (a) 학생 상세 화면의 탭 구성과 성적 관련 탭
- 머리: 학생 이름(헤더), "상담 기록" 버튼, 아래 회색 줄 "N학년 N반 N번 · 희망 진로 ○○(없으면 미정)".
- 탭 위 AI 카드 "기록 흐름 요약": 1·2학년 확정본·올해 세특·누가기록·상담을 읽고 "진로 키워드: A → B → C · 겹침: …" + 보완점 1~3개 → "상담 메모에 붙이기". 가명ID만 보내고 저장 안 함. 기록이 없으면 "요약할 기록이 없어요".
- 탭 5개 (PC 라벨 / 모바일 짧은 라벨). 주소 `?tab=`:
  1. `생기부 초안 N` / 초안 (기본)
  2. `성적·수능 최저` / 성적 — 잠금이면 탭 자체가 없음, `?tab=scores`로 와도 초안 탭으로
  3. `상담 N` / 상담
  4. `야자` / 야자
  5. `누가기록·봉사 N` / 누가기록
- 초안 탭: 왼쪽 "생기부 초안 모음"(받은 확정본 + 올해 교과세특, 최신순, 3대 역량 보기 스위치), 오른쪽(성적 열림일 때만) 작은 "모의고사 평균 등급" 막대(최근 4회) + "수능 최저 판정" 목표 목록. 아래 "지난 학년도 확정본"(영역별 건수) · "정정 요청"(대기/완료 태그, 사유, 날짜).
- **성적 탭**:
  - AI 배너 "성적 추이 해석": 기본 문구 "평균 등급 흐름과 상담에서 짚을 과목을 한 줄로 알려 줘요"(시험 2회 미만이면 "모의고사가 두 번 이상 있어야 추이를 볼 수 있어요"). "해석 보기" → AI 한 줄(60자, 흐름 + 짚을 과목 하나). AI 없으면 규칙 `trendSummary` 문장.
  - 왼쪽 카드 "모의고사 평균 등급": 시험별 막대(invert = 1등급이 가장 긴 막대, 값 소수 1자리), 아래 최근 시험 6과목 등급(국어·수학·영어·한국사·탐구1·탐구2, 없으면 "–"). 카드 머리 "성적 업로드" 링크.
  - 오른쪽 카드 "수능 최저 판정"(머리에 "N월 모의고사"): 목표 대학 1~3순위 행 = "대학 학과", 이유 한 줄, 판정 태그(충족 초록·근접 노랑·미충족 빨강).
  - 빈 상태: "아직 올린 성적이 없어요", "목표 대학이 없어요".
- 상담 탭: 상담 기록 목록(날짜·영역·내용·작성자·수정됨 표시) + "기록 쓰기".
- 야자 탭: 타일 "이번 주 신청 n일 / 출석 n일", AI 배너 "출결 한 줄"(규칙: "4주 출석 n회 · 결석·조퇴 n회 (○요일에 몰림)"), "야간 자율학습 관리" 링크.
- 누가기록 탭: 누가기록·봉사 목록 + 역량 보기. 빈 상태 "아직 누가기록·봉사가 없어요".
- 내신은 이 화면 어디에도 없다.

### (b) 모의고사 성적
- 시험(Exam) 필드: `id, year, month, name`. 이름은 서버가 `"{month}월 모의고사"`로 만든다. 같은 연도·월이면 같은 시험. **시험 종류(교육청 학평/평가원 모평/수능) 구분 필드 없음.** 화면 표기는 "N월".
- 성적(MockScore) 필드: `examId, studentId, grades, createdAt`. grades = 과목별 등급(1~9 정수, 빈 칸 = null = 결시·미입력).
- 영역 6개, 공통과목 고정(PRD 메모 2026-10-16): 국어(ko) · 수학(ma) · 영어(en) · 한국사(hi) · 탐구1(t1, 통합사회) · 탐구2(t2, 통합과학). 수학 선택과목·사탐/과탐 세부 과목 나누지 않음.
- **원점수·표준점수·백분위 필드 없음. 등급만 저장.** 업로드 때 제목에 "원점수|표준|백분위|석차|등급컷"이 들어간 열은 일부러 건너뛴다. 같은 과목 열이 여럿이면 제목에 "등급"이 들어간 열을 우선.
- 평균 등급 = 국·수·영·탐(탐1·탐2 평균) 4개 평균, 한국사 제외, 있는 것만, 소수 1자리.
- 다시 올리면 덮어쓰지 않고 새 행을 추가하고 읽을 때 최신을 쓴다(지우지 않음).
- 업로드 양식(xlsx) 열 구성, 시트 "성적": `번호 | 이름 | 국어 | 수학 | 영어 | 한국사 | 탐구1 | 탐구2`
  - 번호·이름은 우리 반 명단으로 미리 채움. C~H열은 1~9 정수 데이터 유효성 검사("등급은 1~9예요"). G1·H1 메모: "탐구1 = 통합사회 (공통과목)", "탐구2 = 통합과학 (공통과목)". 1행 고정.
  - 두 번째 시트 "작성 방법": 1행 제목 바꾸지 말기 / 등급만 1~9 숫자로(결시는 비워 두기) / 탐구1·2는 공통과목 등급 / 번호와 이름이 명단과 하나라도 다르면 반영되지 않음.
- 업로드 화면 흐름: 단계 표시 `파일 선택 → 열 맞추기 → 검증 → 반영`.
  - 파일 카드: 파일명(없으면 "성적 파일을 올려 주세요"), "xlsx 또는 성적표 사진·PDF · N학년 N반", 시험 드롭다운("2026 10월 모의고사 · 28명 반영됨"), "파일 고르기/다시 올리기", "시험이 없으면 [월] 시험 추가".
  - 열 이름이 달라도 제목 규칙으로 자동 매칭("'성명' → 이름" 식으로 바뀐 열 안내). 못 맞추면 열 맞추기 편집기(필드별 드롭다운 "C열 국어", 빈 칸 빨간 테두리) → "이 열로 다시 검사".
  - 검증 결과 표: `번호 | 이름 | 국어 | 수학 | 영어 | 한국사 | 탐구1 | 탐구2 | 상태`, 필터 `전체 N` / `확인 필요 N`. 행 상태 6종: 정상 / 빈 칸 / 범위 오류 / 이름 불일치 / 명단에 없음 / 번호 중복. 범위 오류 칸은 빨간 굵은 글씨. 모바일은 확인 필요 행만 목록.
  - 반영 규칙: 번호·이름이 하나라도 명단과 다르면 **전체 반영 막음**. 범위 오류 행은 빼고 반영, 빈 칸은 결시로 반영. 버튼 "N명 반영하기", "오류 행만 내려받기"(원래 값 + 상태 + 사유 xlsx).
  - 안내 문구 예: "번호·이름이 명단과 다른 행이 N개 있어요. 고쳐서 다시 올려야 반영돼요", "범위 오류 N행은 빼고 반영해요", "빈 칸은 결시로 반영돼요", "파일에 없는 학생 N명 (전체 N명)", "10월 모의고사는 이미 N명 반영돼 있어요. 다시 반영하면 새 값이 쓰여요".
  - 완료 카드 "반영 완료 — N명의 10월 모의고사 성적을 반영했어요" + "수능 최저 판정 보기".
  - 오류 문구: "엑셀 파일을 골라 주세요", "xlsx 또는 성적표 사진(png·jpg)·PDF만 올릴 수 있어요", "2MB까지 올릴 수 있어요", "한 번에 200행까지 올릴 수 있어요", "성적 행이 없어요", "시험을 골라 주세요".
  - AI 사용: (1) "AI 제안" = 엑셀 1행 제목만 보내 열 매칭 제안(이름·성적 값 안 보냄), 제안 칸에 "AI" 태그 → "확인 후 업로드". AI 없으면 "AI가 꺼져 있어요. 오른쪽에서 열을 직접 골라 주세요". (2) 성적표 사진·PDF(8MB) → AI가 번호·등급만 읽음(이름 열 읽지 말라고 지시), 이름은 서버가 번호로 명단에서 붙임, 같은 검증 표로 확인. AI 없으면 사진은 받지 않고 xlsx만.

### (c) 내신 성적 추이
- 있다. 단 **학생 본인 화면(/student/scores)에만**, 그리고 **차트가 아니라 목록**이다.
- 카드 "내신", 머리 오른쪽 "학기별". 행 = 제목 "N학년 N학기", 메타 "국 2 · 수 3 · 영 2"(null 과목은 빠짐), 오른쪽 굵게 "2.4등급"(전 과목 평균 등급, 소수 1자리). 학년·학기 오름차순.
- 데이터(SchoolGrade): `studentId, grade(학년), semester(1|2), ko, ma, en, average(전 과목 평균 등급)`. 과목별은 국·수·영 3개만, 평균은 따로 저장된 값.
- 업로드·입력 화면 없음. 저장소 인터페이스에 읽기(listSchoolGrades)만 있고 쓰기가 없다 → DB에 직접 넣는 것으로 추정.
- 담임 학생 상세에는 내신이 나오지 않는다. 내신 막대/선 차트 없음. 내신을 최저 판정·브리핑에 쓰지 않음.
- 참고: 모의고사 추이 차트(TrendCard)는 있음 — 세로 막대, 1등급이 가장 긴 막대(invert, max 9), 기본 "모의고사 평균 등급 추이", "과목별 보기"를 누르면 칩(국어·수학·영어·탐구)으로 과목 바꿔 보기. 시험이 0개면 "아직 모의고사 성적이 없어요".
- (참고: `lib/domain/transcript.ts`는 내신이 아니라 발표 음성 받아쓰기 정리 기능이다.)

### (d) 수능 최저 판정
- 판정 상태 5종과 태그 색: 충족(초록) / 근접(노랑) / 미충족(빨강) / 자료 부족(흰 바탕 회색 글씨) / 판정 불가(흰 바탕 연회색 글씨). 색 외에 글자로 상태명을 항상 같이 쓴다(아이콘은 없음).
- 기준(MinRule) 필드: `university, major, pool(반영 영역: 국·수·영·탐 중), pick(몇 개), maxSum(등급 합 이내, 0.5 단위 입력), required(꼭 넣을 영역), historyMax(한국사 n등급 이내 | 없음), inquiry(탐구 1과목 | 2과목 평균 | 2과목 평균 소수점 버림), note(메모)`. 내리기(archive)만 있고 삭제 없음.
- 학생 목표(StudentTarget): `rank(1~3), university, major, ruleId | null`. 학생이 직접 정함. 기준 목록에 없는 대학을 직접 쓰면 ruleId=null → 판정 불가.
- 판정 규칙 (`judgeMinimum`, 순수 함수):
  1. 기준이 없거나 기준 자체가 이상하면 → **판정 불가** ("대학 기준이 없어요"). 이상한 기준 = 영역 없음, pick > 영역 수, 합이 0 이하나 9×pick 초과, 필수 영역이 반영 영역 밖, 필수 수 > pick, 한국사 1~9 밖.
  2. 그 시험 성적이 없으면 → **자료 부족** ("성적이 없어요").
  3. 빈 과목을 9등급(비관)으로 채워도 통과 → **충족**. 이유 예 "국어 2 + 영어 2 = 4" (빈 과목이 있으면 "빈 과목이 있어도 충족").
  4. 빈 과목을 1등급(낙관)으로 채우면 통과, 비관이면 실패 → **자료 부족** ("한국사·탐구2 성적이 없어요").
  5. 낙관으로도 실패 → 관련 과목 하나를 1등급만 올려서 통과하는 과목이 있으면 **근접** ("수학 1등급만 올리면 충족", 고칠 과목은 등급이 나쁜 과목부터).
  6. 아니면 **미충족**. 이유: 한국사 탈락이면 "한국사 5등급 (기준 4 이내)", 아니면 "합 7 (기준 5)".
  - 조합 고르기: 필수 영역은 꼭 넣고 나머지는 좋은 등급부터 pick개 → 합 최소. 통과 = 합 ≤ maxSum 그리고 한국사 조건.
  - 탐구 등급: best = 두 과목 중 좋은 것, avg = 평균, avgFloor = 평균 소수점 버림.
- 수능 최저 화면(/homeroom/minimum):
  - 헤더 "수능 최저 판정", "대학 기준 관리"(아래 기준 목록으로 이동). 반 고르기.
  - 숫자 타일: 판정 대상 N명(목표 있는 학생) / 충족 N명 / **미충족 N명(= 미충족 + 근접 합침)** / **자료 부족 N명(= 자료 부족 + 판정 불가 합침)**. 첫 타일에 "판정 결과 내려받기".
  - 최저 분석(AI 배너): 기본 "한 과목만 1등급 올리면 충족되는 학생 N명 — 우선 상담 대상". "상담 명단 만들기" → 학생별 체크박스 + "우선 1/2/3" 태그 + 고칠 수 있는 이유(100자) → "확인 후 저장(N명)". AI 우선순위: 1 = 한 과목만 올리면 됨, 2 = 자료 부족, 3 = 여러 과목. AI 없으면 근접 학생만 우선 1로("규칙으로 고름"). 저장된 최신 명단은 아래 "상담 명단" 카드로 보임.
  - 시험 탭(Segmented): 성적이 있는 시험 최근 4개(모바일 3개), 첫 탭은 "10월 모의고사", 나머지 "9월" 식. 검색 "학생·대학 검색".
  - 표 "학생별 판정", 머리 토글 "미충족만 보기"(미충족 + 근접). 열: `학생(아바타·이름·번호) | 목표 대학·학과("외 n") | 기준("수학 포함 2개 합 4") | 국어 | 수학 | 영어 | 탐구 | 판정`. 탐구 칸은 기준의 탐구 방식대로 계산한 값. 행에 마우스를 올리면 이유(title). 모바일: 이름, "목표 · 기준", "국 2 · 수 3 · 영 2 · 탐 2.5", 판정 태그.
  - 표는 1순위 목표만 판정. 내려받기는 1~3순위 전부: 열 `번호 | 이름 | 국어 | 수학 | 영어 | 한국사 | 탐구1 | 탐구2 | 순위 | 목표 대학·학과 | 기준 | 판정 | 설명`.
  - "대학별 기준" 카드: 3열 카드, "대학 학과" + "내리기", 설명 "국·수·영·탐 중 2개 합 5 (수학 포함)", 덧붙임 "한국사 4 이내 · 탐구 1과목 · 메모", "우리 반 n명 목표".
  - "기준 추가 +" 다이얼로그: 맨 위 "모집요강으로 채우기"(문구 붙여넣기 또는 캡처 png/jpg/PDF 8MB) → "기준 채우기". 아래 대학/학과·전형, 반영 영역 칩 4개, 몇 개, 등급 합 이내, 꼭 넣을 영역 칩, 한국사 드롭다운, 탐구 드롭다운, 메모. 고르는 대로 미리보기 박스("국·수·영·탐 중 2개 합 5") 또는 첫 문제 문장("고르는 개수가 영역 수보다 많아요"). 문제가 있으면 "기준 저장" 비활성.
  - 모집요강 AI: 공개 문서라 그대로 보냄. AI 없을 때 대체 규칙 `parseMinRuleText` = 정규식으로 "N개 (영역) 합 M" / "~ 중" 앞 영역 / "수학 필수·포함" / "한국사 N등급" / "2과목 평균(절사·버림)"을 뽑음. 대학·학과는 못 뽑음("대학·학과는 직접 써 주세요"). 못 찾으면 "문구에서 '2개 합 5' 같은 기준을 찾지 못했어요. 직접 입력해 주세요". AI 실패 시 "AI 대신 규칙으로 채웠어요 (사유)".
  - 빈 상태: "아직 올린 모의고사 성적이 없어요", "해당하는 학생이 없어요", "아직 기준이 없어요. 기준을 추가해 주세요", "넣을 학생이 없어요".
- 학생 화면의 "필요한 것" 문장(minimumNeedLine): 충족 "지금 성적으로 충족해요 (…). 이 등급을 지키면 돼요" / 근접 "수학 또는 영어 1등급만 올리면 충족해요" / 미충족 "국어·수학 등급 합을 2 줄여야 해요 (지금 7, 기준 5)" / 자료 부족 "… — 다음 모의고사 뒤에 다시 볼게요" / 판정 불가 "기준이 아직 없어요. 담임 선생님께 알려 주세요".
- 진학 내비 관점 메모: 이 저장소는 "합격 가능성"을 말하지 않고 기준 충족 여부만 판정한다. 다만 홈 타일 이름 "최저 충족 예상"은 예측처럼 읽힐 수 있다(우리 NEVER-2 검토 대상).

### (e) 누가기록(logs)·행동특성(behavior)의 입력 단위와 필드
- 누가기록(조각 모으기, /homeroom/logs):
  - 입력 단위 = "조각" 한 개 = 날짜 + 짧은 글. 학생 여러 명을 골라 같은 조각을 한 번에 남길 수 있다(최근 조각 목록에서 "학생A 외 2명" 한 줄로 묶어 보임, 같은 날 같은 글 = 같은 조각).
  - 영역은 담임 기준 2개: 자율·자치 | 진로 (탭/선택). 행발 영역 누가기록은 따로 있음(행발 초안 근거로 쓰임).
  - 관찰된 필드(ActivityLog, 추정 포함): `id, studentId, area, date, content, authorId, commonActivityId(공통 활동에서 온 조각이면)`. 내용 앞의 활동명 태그를 떼어 activity로 따로 보여 줌.
  - 화면: 머리 "조각 모으기"(eyebrow "담임 · 누가기록"), "여러 명 따로 쓰기", "글 짓기" 버튼. 위에 공통 활동·차시별 활동 카드(반 단위). 보드: 학생별 조각 수(적은 순/번호 순 정렬), 학생 이름 누르면 그 학생 조각 창, 최근 조각 4줄, "오늘 n". 받은 초안에서 확정한 것은 "특색 활동" 칩으로 섞여 보임.
  - AI: 보드에 aiOn이 넘어가지만 이 저장소 조각 묶기 로직(collect.ts)은 "AI 없음"이라고 명시. 발표 녹음 받아쓰기 → 누가기록 문체 요약(이름·학번 가린 뒤 전송, 저장 안 함) 기능이 별도로 있음(transcript.ts).
- 행동특성(행발):
  - /homeroom/behavior는 화면 없이 글 짓기 행발 탭으로 넘긴다.
  - 입력 단위 = 학생 1명 × 학년도 1개의 "고른 키워드 + 에피소드 메모 + 누가기록 같이 쓰기 여부". 필드(BehaviorPick): `studentId, year, keywords(라벨 문자열 배열, 최대 40), memo(최대 600자), useLogs(boolean)`.
  - 키워드 메뉴판은 교사마다 따로. 기본 5묶음(모두 긍정·관찰 낱말): 학교생활 태도 / 공동체·관계 / 사고·학습 / 자기관리 / 성장. 교사가 순서 바꾸기·숨기기·내 키워드 더하기(12자, 중복 거절, 전체 200개까지). 8개 넘게 고르면 "많으면 글이 흐려져요" 경고.
  - "초안 만들기"(AI): 키워드 + 메모 + (켜면) 행발 누가기록 → 행발 초안(900B 범위). 이름·학번 지운 메모와 가명ID만 보냄. 결과는 돌려주기만 하고 교사가 본문에 넣고 저장·확정. AI 원안과 근거(메모·누가기록)를 따로 보관(provenance). 실패 시 "초안을 만들지 못했어요. 메모를 더 적어 주세요". AI 없을 때 대체 규칙은 이 범위 파일에서 확인 못 함(추정: 샘플 문장 또는 비활성).

## 4. 개인정보 처리 방식

- 서버 저장: 모의고사 등급(mock_scores), 내신(school_grades), 대학 기준(min_rules), 학생 목표(student_targets), 상담 명단(min_counsel_lists), 공부 계획(study_plans), 야자 신청·출석, 봉사 기록, 누가기록·행발 키워드가 모두 서버 DB(Supabase)에 저장된다. 성적·출석은 지우지 않고 추가만 하며, 다시 올리면 새 행을 더하고 최신을 읽는다.
- 잠금 이유 (features.ts 주석 원문 요지): 2026-10-18 사용자 요청 "개인정보 관련해서 성적은 민감해서 기능들을 일단 락해놓자". 성적 업로드·수능 최저·학생 성적·최저 화면, 그리고 홈·학생 상세의 성적 숫자를 잠갔다. **이미 올린 자료는 지우지 않는다.** 서버 환경변수 하나로 다시 연다. 잠금 시 서버 동작도 막는다("잠긴 기능이에요" 403, 학생 화면은 /locked).
- AI에 보내는 것: 학생은 이름·학번 대신 가명ID(pseudonymId)만. 서버가 결과의 가명ID를 다시 이름으로 바꿔 보여 준다. 성적은 등급 숫자만, 엑셀 열 맞추기는 1행 제목만 보낸다. 브리핑·추이 해석·출결 한 줄·봉사 한 줄은 "저장하지 않아요".
- 예외: 성적표 사진·PDF는 이미지 안의 이름 열이 그대로 전송될 수 있음을 코드 주석에서 인정. 번호 열만 읽고 이름은 받지 않도록 지시하고, 이름은 서버가 명단으로 붙인다. 모집요강은 공개 문서라 그대로 보낸다.
- 접근 제어: 담임은 자기 반 학생만(서버에서 다시 확인, "우리 반 학생만 볼 수 있어요"). 권한 키 예: scores.upload, minimum.view, homeroom.view, night.manage, service.receive, student.self.
- 감사 로그: AI 호출·업로드·내보내기·기준 추가/내리기·명단 저장 때마다 audit 기록(대상은 가명ID 또는 반 키).
- 내려받기 파일(양식·판정 결과·오류 행·야자 출석)에는 실명이 들어간다. Cache-Control no-store.
