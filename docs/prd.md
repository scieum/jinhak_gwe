2028 진학 내비 PRD — 2022 개정 교육과정 첫 대입 세대를 위한 진학 설계 플랫폼

작성: 강원진학지원센터 AI자료개발팀 · 버전 v0.1 (2026-11-18) 이 문서는 디자인·코딩 에이전트(Claude Code 등)가 읽고 바로 이어서 작업할 수 있도록 작성한 PRD입니다.

아래 PRD를 기준으로 2028학년도 대입(2022 개정 교육과정·내신 5등급제 첫 적용)을 준비하는 학생과 교사가 쓰는 진학 설계 웹앱을 만들어 주세요.

이 제품은 단순한 대학 정보 검색 사이트가 아닙니다. 최종 목표는 전형계획 확인 → 내 성적 입력 → 대학별 환산 → 5·9등급 위치 해석 → 지원 가능 대학 탐색 → 수시 6장 설계 → 교사 상담·결과 축적이 하나로 이어지는 진학 설계 플랫폼입니다.

1. 배경

2028학년도 대입은 고교학점제·2022 개정 교육과정·내신 5등급제가 처음 적용되는 입시입니다. 현장에서는 다음 문제가 동시에 생기고 있습니다.

성적 체계가 바뀌었습니다. 과목 평가는 성취도(A~E)와 석차등급(1~5등급)을 함께 기재합니다. 체육·예술·교양 교과(군)와 과학탐구실험은 성취도만, 사회·과학 융합선택 9과목은 석차등급 없이 기재합니다. 성적표에는 학점, 원점수/과목평균, 성취도/분포비율, 수강자수가 함께 적힙니다.
비교할 입결이 없습니다. 공개된 입시결과(50%·70% 컷)는 모두 9등급제 기준입니다. 5등급 성적을 가진 학생이 "지금 어디쯤인지" 알려면 9등급 기준으로 환산해서 해석해야 하는데, 공식 환산표가 없습니다. 시행지침에는 두 등급제의 누적비율 표만 따로 있습니다.
대학마다 반영 방식이 다릅니다. 2028 시행계획에서 대학별 교과성적 반영 방식이 여러 유형(등급 점수표, 성취도 병행 반영, 졸업생 Z점수 변환 등)으로 갈립니다. 평균 등급 하나로는 유불리를 판단할 수 없습니다.
도구가 흩어져 있습니다. 공개 포털의 성적 분석, 대학별 환산 계산기, 유료 AI 수시 분석 서비스, 교사가 엑셀로 만든 상담카드·결과 집계 파일이 따로 놉니다. 강원 학생과 교사는 이걸 오가며 상담 자료를 직접 짜맞춥니다.
유료 서비스 격차가 있습니다. 생기부 AI 분석과 합격 가능성 진단은 대부분 유료입니다. 지역 공교육 학생도 같은 수준의 도구를 무료로 쓸 수 있어야 합니다.

따라서 이 웹앱은 다음 문제를 해결해야 합니다.

학생이 2028 전형계획을 대학·전형별로 쉽게 확인할 수 있어야 합니다.
성적표를 한 번만 입력하면 대학별 교과·출결 환산점수가 자동으로 계산되고, 계산 근거를 볼 수 있어야 합니다.
5등급 성적을 9등급 기준으로 환산해 기존 입결과 비교할 수 있어야 합니다. 환산은 추정치이므로 범위와 근거를 함께 보여줘야 합니다.
지금 성적으로 지원 가능한 대학·학과를 교과·종합전형별로 볼 수 있어야 합니다.
수시 6장 조합을 설계하고 점검할 수 있어야 하며, 교사가 학급 단위로 상담·수합·결과 관리를 할 수 있어야 합니다.
생활기록부 텍스트를 AI로 분석해 역량 진단과 면접 예상 질문을 받을 수 있어야 합니다.
2. 제품 비전

2028 진학 내비는 2022 개정 교육과정 세대 학생과 교사가 전형계획·성적·환산·지원 전략·상담 기록을 한곳에서 설계하는 공교육형 진학 설계 플랫폼입니다.

설계 원칙:

계산은 투명하게. 모든 환산 결과에는 "어떻게 계산했는지" 펼쳐 보기를 붙입니다.
추정은 추정답게. 5→9 환산과 지원 가능성 판정은 단일 숫자가 아니라 범위 + 근거 + 신뢰도로 보여줍니다.
성적은 내 기기에. MVP에서는 학생 성적과 생기부를 서버에 저장하지 않습니다.
2028만 보고 끝나지 않게. 학년도(year)를 축으로 데이터를 설계해 2029·2030학년도에도 그대로 씁니다.
3. 핵심 유저스토리
3-1. 학생(고1~고3)으로서

학생으로서, 내 성적표를 한 번만 입력해 두고 관심 대학마다 내 환산점수가 얼마인지, 작년 합격선과 비교하면 어느 위치인지 바로 알고 싶다. 5등급 평균 1.8이 예전 9등급으로 몇 등급쯤인지도 궁금하다.

3-2. 수시 지원을 앞둔 고3으로서

고3 수험생으로서, 교과전형과 종합전형으로 나눠 갈 수 있는 대학을 상향·적정·안정으로 보고, 수시 6장을 직접 배치해 보면서 수능최저 충족 가능성, 면접·논술 일정 겹침, 지나친 상향·안정 쏠림 같은 위험을 미리 경고받고 싶다.

3-3. 학종을 준비하는 학생으로서

학생부종합전형을 준비하는 학생으로서, 내 생기부를 붙여넣으면 학업·진로·공동체 역량이 어떻게 드러나는지, 어떤 근거 문장이 강점인지, 무엇이 비어 있는지, 면접에서 어떤 질문이 나올지 알고 싶다.

3-4. 담임·진학 담당 교사로서

교사로서, 우리 반 학생들의 성적을 한 번에 불러와서 학생별 대학 환산과 지원 가능 대학을 상담 화면에서 바로 보고 싶다. 학생이 낸 수시 6장 카드를 모아 한 화면에서 상담하고, 변경 이력과 상담 메모를 남기고, 발표 결과를 반·학년 단위로 집계하고 싶다.

3-5. 센터 데이터 관리자로서

센터 데이터 관리자로서, 대학별 2028 전형계획과 환산 규칙을 구조화된 데이터로 등록하고, 대학 공식 계산 결과와 대조해 검수한 뒤에만 공개하고 싶다. 모집요강이 나오면 규칙 버전을 올려 갱신하고 싶다.

4. 사용자들의 상황
학생은 "평균 등급"으로만 자기 위치를 생각하는 경우가 많고, 대학별 반영 방식 차이를 잘 모릅니다.
5등급제는 1등급 구간이 상위 4%에서 10%로 넓어져 동점자가 많고, 기존 입결과 비교하는 기준이 없어 불안이 큽니다.
교사는 상담 시즌(고3 1학기~9월)에 짧은 시간 안에 여러 학생을 상담해야 하고, 학생별 자료를 엑셀로 직접 만듭니다.
교무실 PC는 여러 사람이 함께 쓰는 경우가 많습니다. 학생 성적이 남는 방식은 조심해야 합니다.
강원 지역 학생은 지역 대학과 수도권 대학을 함께 고려하고, 학교마다 진학 정보 격차가 있습니다.
대학별 모집요강은 고3 4~5월에 나옵니다. 그 전까지는 시행계획 기준으로 안내하고, 요강이 나오면 갱신해야 합니다.

6. 기능 요구사항
6-1. 전형계획 탐색 (2028 시행계획)

누구나 로그인 없이 볼 수 있습니다.

필수 기능:

대학 검색: 이름, 지역(강원/수도권/권역), 설립 유형, 캠퍼스
대학 상세: 2028 전형 목록, 전년 대비 주요 변경사항 요약
전형 상세:
전형 유형(교과/종합/논술/실기/정시), 세부 유형(지역균형·학교장추천 등)

면접·논술 일정

6-2. 내 성적 입력

공개 대입 포털의 성적 입력 방식처럼 한 번 입력하면 모든 계산에 재사용합니다. 2022 개정 교육과정 성적표 구조를 그대로 따릅니다.

필수 기능:

학년·학기별 과목 입력 표(성적표와 같은 열 순서)
과목 검색 자동완성: 2022 개정 보통교과 과목 목록에서 고르면 교과(군)·과목 유형이 자동으로 채워집니다
생기부 PDF 자동 입력(2026-11-18 추가): 학교생활기록부 PDF의 교과학습발달상황 표를 AI 없이 규칙(텍스트 추출·표 읽기)으로 읽어 성적 표를 채웁니다. 읽은 값은 학기별 확인 화면에서 사람이 확인한 뒤에만 반영하고, PDF 파일은 읽은 뒤 저장하지 않으며 성적만 이 기기에 저장합니다. 글자 층이 없는 스캔 PDF는 직접 입력으로 안내합니다.
보기 전환: 성적 표는 학기별 · 학년별(학기·학년 소계) · 전체로 바꿔 볼 수 있습니다.

6-3. 출결 입력
학년별 수업일수, 결석·지각·조퇴·결과(질병/미인정/기타)
대학별 출결 반영 규칙에 따라 감점이 자동 계산됩니다(예: 미인정 지각·조퇴·결과 n회 = 결석 1일 환산 후 구간별 감점)
출결 감점이 생기는 대학을 목록으로 경고 표시
6-4. 대학별 환산 엔진 (교과 + 출결)

대학·전형마다 **환산 규칙(ScoringRule)**을 데이터로 저장하고, 하나의 공통 엔진이 규칙을 해석해 계산합니다. 대학별로 코드를 따로 짜지 않습니다.

필수 기능:

6-5. 5등급 → 9등급 환산

공식 환산표가 없으므로 두 가지 방법을 함께 계산하고 비교해서 보여줍니다.

방법 A — 누적비율 보간(앱 자체 공식, 근거 공개)
9등급 누적비율: 1등급 4% / 2등급 11% / 3등급 23% / 4등급 40% / 5등급 60% / 6등급 77% / 7등급 89% / 8등급 96% / 9등급 100%
5등급 누적비율: 1등급 10% / 2등급 34% / 3등급 66% / 4등급 90% / 5등급 100%
각 등급 구간의 중앙 누적비를 기준점으로 삼아 선형 보간합니다(세부 공식은 9장 R-CONV)
A-1 평균 기반: 학점 가중 5등급 평균 → 누적비 → 환산 9등급
A-2 과목 기반: 과목별 등급 → 과목별 누적비 → 과목별 환산 9등급 → 학점 가중 평균
A-2는 과목 수강자수로 그 과목의 실제 등급 누적비 구간을 다시 계산해 보정합니다(R-CONV-010).
A-3 분포비율 보정(검수 전 꺼 둠, 2026-11-18 개편): 2022 개정 성적표에는 표준편차가 없어 z점수 방식은 쓰지 않습니다. 고정분할 과목에서 원점수를 성취도 경계(90·80·70·60점)의 누적비(성취도별 분포비율) 사이로 보간해 등급 안 위치를 좁힙니다(R-CONV-011). 공개 선례가 없어 검증·검수 전에는 "준비 중"으로 표시합니다.
방법 B — 배치표 기준(경험 데이터)
실제 학생 집단의 "5등급 평균 → 누적비 → 환산 9등급" 대응표를 데이터로 등록해 조회
기본 원천은 교육청·교사 협의회의 실측 대응표입니다(예: 부산교육청 학력개발원 2025-08~ 학기별, 경기진학지도협의회 2025-08, 광주시교육청 2026-04). 학기 기준(누적 학기 수)·과목 범위·지역·표본 수를 필수로 저장하고, 원자료에 붙은 대학 라인은 쓰지 않습니다(R-CONV-009). 실측표와 비교하면 A-1은 평균 1.15~1.7 구간에서 0.15~0.23등급 높게(불리하게) 나오므로, 방법 간 차이 설명에 이 점을 보여줍니다.
출처·연도·표본 규모를 함께 표시하고, 사용 허락이 확인된 표만 등록
장기적으로는 강원 지역 학교의 익명 집계로 강원형 배치표를 자체 구축(로드맵 Phase 3)
결과 화면
방법별 값 + 범위(최솟값~최댓값) + 방법 간 차이가 큰 이유 설명
신뢰도 표시: 입력 과목 수, 석차등급 미산출 과목 비율, 수강자수가 적은 과목 비율
교과군별(전 교과/국수영사과/국수영사/국수영과 등) 환산 9등급
6-6. 지원 가능 대학 (교과 · 종합)

교과전형 탭

대학 반영 교과 기준으로 계산한 내 환산 9등급(범위)을 전년도 입결(50%·70% 컷, 경쟁률, 충원율)과 비교
판정: 안정 / 적정 / 소신 / 위험 (기준은 R-JDG, 값은 관리자 설정)
수능최저가 있는 전형은 최저 확인 필요 배지와 내 모의고사 기준 충족 가능성 표시

우리 반 홈(teacher-dashboard): 숫자 타일 4개(학생 수, 카드 제출, 최저 미충족, 상담 필요), 우리 반 브리핑(먼저 볼 학생 — 규칙: 최저 근접·카드 위험 경고·성적 하락), 학생 한눈에 목록.
학생 기록 상세(student-record): 탭 = 성적 추이 / 수능 최저 / 상담 / 누가기록 / 수시로.
  - 성적 추이: 내신 학기별 평균 등급(전 교과·국수영사과) 선 차트 + 모의고사 회차별 영역 등급(국·수·영·탐1·탐2) 선 차트. 등급 축은 1이 위.
  - 수능 최저: 목표 대학(최대 3개)별 판정.
성적 불러오기(score-import): 모의고사 등급·내신 성적표 업로드 4단계(파일 → 열 맞추기 → 검증 → 반영), 번호·별칭을 채운 양식 내려받기. 모의고사는 시험(연·월·종류 학평/모평/수능)과 영역별 등급, 원점수·백분위는 선택.
수능 최저 판정(minimum-board): 반 학생 × 1순위 목표 판정 표. 판정 = 충족 / 근접(한 영역 1등급만 오르면 충족) / 미충족 / 자료 부족 / 판정 불가 — 색 + 아이콘 + 이름. 기준은 관리자 검수 데이터(csat_minimum)가 기본, 담임이 추가한 기준은 "교사 입력 · 미검수" 배지. 상담 명단은 규칙(근접 먼저)으로 만들고 교사가 고친 뒤 저장. xlsx 내보내기. 화면 문구는 "충족 현황"(예측 표현 금지, NEVER-2).
누가기록(homeroom-logs): 영역(자율·자치 / 진로)과 날짜를 고르고 여러 학생에게 한 번에 관찰 기록을 남기는 보드, 학생별 기록 수.
내 성적 추이(score-trend, 학생): 내 내신 학기별 추이 + 모의고사 회차별 추이 차트 + 목표 대학 최저 판정. 모든 숫자는 추정·범위 규칙과 disclaimer-note를 따른다.

# 학생 백업은 암호로 암호화, 상담카드는 학급 코드로 묶음
9. 계산·판정 규칙 (ID 부여, 각 규칙에 검증 테스트 필수)
R-IN 입력 검증
R-IN-001 석차등급 미산출 과목(융합선택 9과목, 체육·예술, 과탐실험, 교양)에는 rank_grade 입력을 막는다.
R-IN-002 achievement_distribution의 합은 100%(±0.1)여야 한다.
R-IN-003 raw_score는 0~100, subject_mean은 0~100, enrolled_count는 1 이상.
R-IN-004 수강자수가 기준(학생부 기재요령 기준값) 이하인 과목은 소수 수강 표시를 하고 신뢰도 계산에 반영한다.
R-CONV 5→9 환산
R-CONV-001 5등급 구간 중앙 누적비: 1등급 5%, 2등급 22%, 3등급 50%, 4등급 78%, 5등급 95%.
R-CONV-002 9등급 구간 중앙 누적비: 1등급 2%, 2등급 7.5%, 3등급 17%, 4등급 31.5%, 5등급 50%, 6등급 68.5%, 7등급 83%, 8등급 92.5%, 9등급 98%.
R-CONV-003 (A-1 평균 기반) 5등급 평균 g5를 R-CONV-001 기준점 사이 선형 보간으로 누적비 p로 바꾸고, p를 R-CONV-002 기준점 사이 선형 보간으로 환산 9등급 g9로 바꾼다. 범위 밖은 1.0 또는 9.0으로 고정한다.
R-CONV-004 (A-2 과목 기반) 과목마다 R-CONV-003을 적용한 뒤 학점 가중 평균을 낸다.
R-CONV-005 (폐기, 2026-11-18) 2022 개정 성적표에 표준편차가 기재되지 않아 z점수 보정은 쓰지 않는다. A-3은 R-CONV-011로 대체한다.
R-CONV-006 (B 배치표) 등록된 배치표 중 license_status = allowed인 표만 쓰고, 평균값은 표 안에서 선형 보간한다.
R-CONV-007 결과는 {a1, a2, a3?, b?, min, max, confidence}로 반환하고 화면에는 범위를 먼저 보여준다.
R-CONV-008 신뢰도 = f(석차등급 산출 과목 수, 소수 수강 과목 비율, 방법 간 차이). 3단계(높음/보통/낮음).
R-CONV-009 배치표는 basis_semesters(누적 학기 수)·subject_scope·region·n·source·license_status를 필수로 갖고, 학생의 누적 학기 수와 같은 표만 조회한다. 같은 학기 표가 없으면 가장 가까운 표를 쓰고 신뢰도를 한 단계 낮춘다. 원자료의 대학 라인은 저장하지 않는다.
R-CONV-010 (A-2 수강자수 보정) 과목 수강자수 n이 있으면 R-CONV-001의 명목 중앙 누적비 대신 시행지침 산출식으로 n에서 계산한 해당 등급의 실제 누적비 구간 중앙을 쓴다. n ≤ 5이거나 석차등급 미산출이면 환산에서 빼고 신뢰도에만 반영한다.
R-CONV-011 (A-3 분포비율 보정) 분할점수가 고정분할이고 원점수·성취도별 분포비율이 있으면, 원점수를 양쪽 성취도 경계 누적비 사이에서 선형 보간해 p를 구하고 석차등급 누적비 구간 안으로 자른다. 분할점수를 모르면 적용하지 않는다. 검수 전에는 계산하지 않는다(NEVER-1).

보간 기준점(중앙 누적비)은 기본값입니다. 배치표 데이터가 쌓이면 방법 A와 B의 차이를 분석해 기준점을 조정할 수 있도록 관리자 설정값으로 둡니다.

R-CALC 대학별 환산
R-CALC-001 엔진은 ScoringRule만 해석한다. 대학 이름에 따른 조건문을 코드에 넣지 않는다.
R-CALC-002 review_status ≠ verified인 규칙은 학생 화면에서 계산하지 않는다.
R-CALC-003 모든 계산은 단계별 중간값(trace)을 반환해 산출 근거 화면에 그대로 보여준다.
R-CALC-004 반올림은 규칙의 rounding을 따르고, 중간 단계에서는 반올림하지 않는다.
R-CALC-005 출결 감점은 규칙의 환산 방식(지각·조퇴·결과 → 결석 환산)을 먼저 적용한 뒤 구간표를 적용한다.
R-JDG 지원 가능성 판정
R-JDG-001 (교과) d = 내 환산 9등급 − 70% 컷. 기본값: d ≤ −0.3 안정 / −0.3 < d ≤ 0.1 적정 / 0.1 < d ≤ 0.4 소신 / d > 0.4 위험. 기준값은 관리자 설정.
R-JDG-002 판정은 환산 범위의 **불리한 쪽 값(max)**으로 하고, 유리한 쪽 값으로는 달라지면 경계를 함께 표시한다.
R-JDG-003 충원율이 높은 전형은 판정 옆에 충원율을 표시한다(판정값 자체는 바꾸지 않음).
R-JDG-004 수능최저가 있으면 가채점·모의고사 기준 충족 여부를 별도 배지로 붙인다. 성적이 없으면 최저 확인 필요.
R-JDG-005 (종합) 라벨은 적합도 높음 / 보통 / 낮음. 정량 지표(R-JDG-001 기준) + 권장과목 충족률로 계산하고, AI 진단은 참고 표시만 하며 판정값에 섞지 않는다.
R-JDG-006 입결 데이터가 없으면 판정하지 않는다.
R-CARD 수시 6장 점검
R-CARD-001 6회 제한 대상 카드는 최대 6장. 제외 기관 목록은 데이터로 관리한다.
R-CARD-002 같은 날짜의 면접·논술이 2개 이상이면 경고.
R-CARD-003 소신+위험이 4장 이상이거나 안정이 0장이면 경고. 안정이 5장 이상이면 "하향 쏠림" 경고.
R-CARD-004 수능최저 미충족 예상 카드가 3장 이상이면 경고.
R-CARD-005 가장 낮은 안정 카드가 예상 정시 수준보다 낮으면 "수시 합격 시 정시 지원 불가" 경고.
R-AI 생기부 분석
R-AI-001 가림 확인 없이는 전송하지 않는다.
R-AI-002 응답은 정해진 JSON 스키마로만 받고, 스키마 검증에 실패하면 1회 재요청한 뒤 오류를 안내한다.
R-AI-003 근거 인용(quote)은 입력 원문에 실제로 있는 문장이어야 한다(문자열 대조로 검증, 없는 인용은 제거).
R-AI-004 합격 가능성·확률 표현을 출력하지 않는다(프롬프트 + 출력 필터).
R-AI-005 프록시는 요청·응답 본문을 저장하지 않고, 호출 횟수만 집계한다.
R-PRIV 개인정보
R-PRIV-001 학생 성적·생기부는 URL 파라미터나 서버 로그에 남기지 않는다.
R-PRIV-002 교사 학급 데이터는 서버에 학교·교사별 RLS로 저장하고 전송은 TLS, 학생 실명·연락처는 저장하지 않는다(번호·별칭만). 기기에 남기는 사본은 WebCrypto로 암호화한다.
R-PRIV-003 교환 파일에는 실명 대신 학급 내 번호·별칭을 기본값으로 쓴다(실명 포함은 교사가 선택).
R-PRIV-004 API 키는 서버 프록시에만 두고 브라우저에 노출하지 않는다.

13. 조건
앱은 학생, 교사, 센터 관리자 세 그룹이 함께 쓰는 것을 전제로 설계합니다.
학생·교사 데이터는 MVP에서 서버에 저장하지 않습니다. 서버는 공개 데이터 배포와 AI 프록시만 맡습니다.
실행 중 AI 호출은 생기부 분석 하나뿐입니다. 환산·판정·점검은 모두 정해진 규칙으로 계산합니다(같은 입력이면 항상 같은 결과).
대학별 환산 규칙은 사람이 검수한 것만 공개합니다. 추정 규칙으로 계산하지 않습니다.
모든 환산·판정 화면에는 데이터 기준일과 "대학 공식 자료가 최종 기준" 고지를 표시합니다.
합격 확률이나 합격 보장으로 읽힐 수 있는 표현을 쓰지 않습니다(판정 라벨, AI 출력 모두).
외부 배치표·입결 자료는 출처를 밝히고, 사용 허락이 확인된 자료만 넣습니다.
학년도(admission_year)를 모든 데이터의 축으로 두어 2029학년도 이후에도 같은 구조로 씁니다.
모바일(학생)과 데스크톱(교사 상담 화면)을 모두 1급으로 지원합니다.

최종적으로 보는 것은 보기 좋은 화면뿐 아니라 AI 에이전트가 읽고 이어서 작업할 수 있는 데이터 구조와 규칙입니다.

14. 이렇게 평가해요
계산의 정확성과 투명성

대학별 환산이 규칙 데이터로 분리되어 있고, 모든 결과에 산출 근거가 나오는지 봅니다. 대학 이름으로 분기하는 코드가 있다면 핵심 요구를 놓친 것입니다.

추정의 정직성

5→9 환산과 지원 가능성 판정이 범위·근거·신뢰도와 함께 표시되는지 봅니다. 단일 숫자로 단정하면 부족합니다.

학생 흐름의 완성도

성적 입력 → 내 위치 → 대학별 환산 → 지원 가능 대학 → 6장 설계 → 상담카드 제출이 끊기지 않고 이어지는지 봅니다.

교사 흐름의 완성도

학급 불러오기 → 학생 상담 → 카드 수합·코멘트 → 결과 집계가 상담 시즌의 실제 업무 순서대로 이어지는지 봅니다.

개인정보 설계

학생 데이터가 기기에만 남는지, 교사 기기 데이터가 암호화되는지, 생기부 전송 전에 가림 확인 단계가 있는지 봅니다.

데이터 운영 지속가능성

시행계획 → 모집요강 → 다음 학년도로 데이터가 버전 단위로 갱신되는 구조인지, 규칙 검수가 테스트 케이스와 2인 검수로 강제되는지 봅니다.

데이터 구조화

전형계획, 환산 규칙, 입결, 성적, 6장 카드, AI 결과가 AI 에이전트가 읽고 이어서 작업할 수 있는 스키마로 정의되어 있는지 봅니다.
