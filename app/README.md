# 진학 내비 개발

Node 24, npm 11, Python 3.12 환경에서 검증합니다.

Windows PowerShell에서는 저장소 루트에서 다음과 같이 실행합니다. 전형계획 조회에는 환경변수나 Supabase 연결이 필요하지 않습니다.

```powershell
cd app
npm.cmd ci
npm.cmd run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

전형계획: http://127.0.0.1:5173/admissions-list

실행용 입결·전형계획 JSON은 Git에 포함되어 있어 별도 수집 없이 실행됩니다. 입결 원본 검증용 `_all.csv.gz`도 포함하며 테스트는 원본 CSV가 없는 환경에서 이를 읽습니다. 원문 PDF/HWP/ZIP·수집 중간 파일·개인 환경설정은 로컬에만 보관합니다. 전형계획 테스트는 수집 메타데이터를 검증하며, 원문 파일까지 내려받은 환경에서는 실제 파일 해시 검사도 실행합니다.

```sh
cd /workspace/jinhak_gwe/app
npm ci --cache /workspace/.npm-cache
npm run build
npm test -- --maxWorkers=2
npm run dev -- --host 0.0.0.0 --port 5173 --strictPort
```

## 계산 API

`/five-to-nine` 상단의 간편 계산은 성적 저장 없이 이용합니다. 5등급 평균·9등급 평균·상위 누적 비율 중 하나를 입력하면 나머지를 즉시 계산합니다. `src/engine/quickConversion.ts`의 구간 중앙값 선형 보간을 사용하며, 이론적 누적 비율은 실제 전국 석차가 아닙니다. 참고 사이트의 부산 예상 보정·경기 실측 모델은 이 기능에 포함하지 않았습니다. 끝 구간은 등급 한계값으로 제한하고, 빈칸·잘못된 숫자·범위 초과에는 결과를 표시하지 않습니다. 입력은 저장하거나 전송하지 않습니다. 아래의 ‘저장한 성적으로 자세히 분석’에서 기존 상세 분석을 열 수 있습니다. 이 간편 계산을 대학별 점수·입결 판정에 자동 적용하지 않습니다.

`src/engine/conversion.ts`의 `convertSubjects(subjects, options)`에 과목·검수된 보간/보정/신뢰도 규칙·배치표 조회 조건을 전달합니다. `src/engine/types.ts`에 입력 형식이 있습니다. `status`는 `ready`, `not_ready`, `invalid` 중 하나입니다. 결과의 각 방법과 신뢰도에도 상태가 있으므로 숫자나 라벨을 쓰기 전에 확인해야 합니다.

- A-1: 학점 가중 평균 → 5등급 중앙 누적비 → 9등급 중앙 누적비 보간.
- A-2: 과목별 환산 후 학점 가중. 수강자수가 있으면 검수된 인원 보정 규칙 필수. 없으면 명목 중앙 누적비 사용. 보정 규칙 미검수 시 명목값으로 몰래 대체하지 않습니다.
- 인원 보정 후보식: `round(n × 누적비 / 100)`로 경계 인원을 구해 실제 누적비 구간 중앙 사용. 수강자수 5명 이하·석차등급 없는 과목은 제외합니다. 성적표의 수강자수와 등급만으로 동석차 집단을 복원할 수 없으며, 원문 대조 전 후보 상태입니다.
- A-3: 고정분할 100/90/80/70/60/0점과 A~E 누적비를 연결하고 석차등급 구간 안으로 제한합니다. 합계 100±0.1%는 100으로 정규화하고 trace에 기록합니다. 추정분할/미상/입력 누락이면 계산하지 않습니다. 비교 대상 과목이 달라지는 것을 막기 위해 선택된 산출 과목 모두 입력이 있어야 A-3 평균을 냅니다. 검수 전 기본 비활성입니다.
- B: 검수 완료이면서 이용 허락된 표만, 정확히 같은 교과 구성으로 조회합니다. 동일 학기 우선, 없으면 가장 가까운 학기(동률은 최신 연도·큰 표본·ID 순). 표 범위 밖 외삽 금지. 대체 학기 사용 시 검수된 신뢰도 정책의 결과를 한 단계 낮춥니다.
- 신뢰도: 산출 과목 수, 소수 수강 비율, 제외 비율, 방법 간 차이를 사용합니다. 기준값은 검수된 외부 정책으로 전달하며 현재 제품 기본값을 임의 확정하지 않았습니다.
- `judgeRange`는 검수된 입결과 관리자 기준으로 max 값을 판정하고, min에서 라벨이 달라지는지 반환합니다. 충원율·수능최저는 별도 정보이며 이 함수에서 판정값을 바꾸지 않습니다.

중간 계산은 반올림하지 않습니다. `trace`로 과목별 환산값·학점 가중치·제외 사유·출처·학기 대체 여부를 확인할 수 있습니다. 학생 화면은 `conversion.ts`, `scoring.ts`, `judgment.ts`를 사용하며 학생 데이터는 Dexie/IndexedDB에만 저장합니다. 성적을 서버로 보내는 API는 없습니다.

## 데이터 검수 상태

`src/data/conversion-rules.ts`는 모두 **draft**입니다. 테스트의 synthetic `verified` 사본은 계산 구현 검증용이며 운영 데이터의 검수 이력이 아닙니다. 실제 활성화는 내용 검수 후 별도 변경으로 처리합니다.

부산 1차 배치표 후보는 기존 조사·화면 설계에 기록된 3개 대응점뿐입니다. 원표 전체가 아니며 구성 교과, 원문 숫자, 사용 허락을 확인하지 못했습니다. 2026-11-18 원문 접근 시 환경 프록시가 403을 반환했습니다. 관련 도메인 접근을 적용한 뒤 원문을 다시 확인하고, 전체 표·출처 페이지·정확한 과목 범위·이용 조건을 등록해야 합니다. 원자료의 대학 라인은 저장하지 않습니다.

## 남은 작업

대학별 교과/출결 계산과 성적 입력·IndexedDB 저장·화면 연결은 구현했습니다. 익명 표본을 사용한 A-3 검증, 신뢰도/판정 정책의 내용 검수, 실제 대학 규칙·입결·전체 실측표 확보와 이용 조건 확인은 남아 있습니다. `src/data/catalog.ts`의 운영 전형 목록은 현재 비어 있습니다. 준비 상태를 실제 계산 결과로 오해하지 않도록 숫자를 만들지 않습니다.

현재 Windows 작업 폴더에서는 Python 하네스 11개가 모두 통과했습니다. Linux에서는 문서 줄바꿈에 따른 기존 해시 불일치가 있을 수 있습니다. 보호된 docs/rules/scripts는 수정하지 않았습니다.

## 실행과 학생 데이터

```sh
cd app
npm ci
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

PowerShell 실행 정책이 npm.ps1을 막으면 `npm.cmd`를 사용합니다. 성적 입력은 `/grade-input`, 환산은 `/five-to-nine`와 `/univ-score`, 교과 판정은 `/doelgak`입니다. `/more`에서 학생 데이터를 지울 수 있습니다.

- 학기별 입력 후 저장하거나 PC 숫자 셀에서 Tab/Enter로 편집을 마칩니다. 잘못된 입력은 작성 중으로 보관할 수 있지만 계산에서 제외합니다.
- ExcelJS와 pdf.js는 파일을 읽을 때 지연 로드합니다. PDF worker도 앱에 번들되어 원본을 외부로 업로드하지 않습니다.
- CSV/XLSX는 앱 템플릿의 한글 열 이름을 사용합니다. XLSX는 첫 시트만 읽고 수식 셀은 거부합니다. 나이스의 임의 양식 열 매핑은 D3 범위 밖입니다.
- PDF는 텍스트 좌표로 줄을 복원한 뒤 지원하는 성적행만 제안합니다. 스캔·미지원 형식은 직접 입력으로 안내합니다. 학기와 숫자를 반드시 확인해야 하며 원본 PDF는 보관하지 않습니다.
- `.jnavi`는 PBKDF2-SHA256(310,000회)와 AES-256-GCM으로 인증 암호화합니다. 암호는 저장하지 않습니다. 복원 데이터는 형식 검증과 확인 후 하나의 DB 트랜잭션으로 바꿉니다.
- 학생 백업 v1에는 `grades`와 `attendance`만 포함합니다. 상담카드/교사 교환 파일은 후속 슬라이스의 별도 형식입니다.

## 대학별 계산 API

`scoreUniversity(grades, attendance, rule)`은 `Calculation<ScoreResult>`를 반환합니다. `ScoringRule`은 `src/engine/scoring.ts`에 있으며 대학명에 따른 코드 분기는 없습니다. `grade_max_score`는 기본점수와 가산점을 포함한 교과 만점이고, 출결 만점을 더하면 `max_score`여야 합니다. 출결 `deduction_table.points`는 감점입니다. 양수 학년 가중치에 해당하는 성적이나 반영 학년 출결이 빠지면 임의로 만점을 주거나 가중치를 재분배하지 않습니다.

검수된 전형을 `catalog.ts`에 등록하면 화면이 자동으로 계산합니다. 입결 비교는 이용 허락, 검수 상태, 9등급 체계 및 반영 교과 범위가 맞아야 합니다. 테스트용 규칙은 `tests/fixtures.ts`에만 있습니다.

## 수집 입결 조회와 자료 갱신

`/admission-results`의 기본 탭인 **수집 자료**에서 모아 둔 입결을 조회합니다. 2024~2026학년도 132,261행, 대학·캠퍼스명 226개, 대학·학년도·원문 주소 조합 1,372건을 가져왔습니다. 모든 전형의 수집 완료를 뜻하지 않습니다. 수집본은 **검수 전 참고자료**이며 성적 판정에 사용하지 않습니다. 기존 2인 검수·이용 조건 확인을 통과한 자료는 별도의 **검수 완료 입결** 탭에서 조회합니다.

대학·학년도·모집시기·전형 유형·전형명·모집단위로 조회하고 50행씩 표시합니다. 원문·상세에서 20개 원본 열과 출처·쪽수·비고를 확인합니다. 출처가 다른 행을 합치거나 컷·평균·최저를 변환하지 않습니다. 원문 값의 소수점 자리와 빈 값을 보존하고, 형식 오류는 확인 필요로 표시합니다. 관리자 `/admin/admin-rules/review`에서도 대학을 선택해 수집본을 불러올 수 있습니다.

갱신은 Python 3 환경에서 `cd app` 후 `npm run data:import-results`를 실행합니다. `work/_data/admission-results/_all.csv`를 읽어 `public/data/collected-results/`에 대학별 사전 압축 JSON과 색인을 생성합니다. 별도 입력은 `python tools/import_admission_results.py --source <CSV> --output <출력 폴더>`로 지정할 수 있습니다. 원본 CSV와 검수 기록은 수정하지 않으며 승인·이용 허용 상태를 생성하지 않습니다. 현재 패키지는 약 54.6MB이고, 화면은 작은 색인과 선택한 대학 파일만 읽습니다. 대학 파일은 SHA-256과 크기를 검사합니다.

`tests/collected-results.test.ts`는 원본 CSV 해시, 모든 행·20개 열의 왕복 보존, 대학별 파일 해시·행 수·원문 수와 공개 검수 상태 분리를 확인합니다. 자료가 바뀌면 패키지를 다시 생성한 뒤 테스트·빌드를 실행합니다.


## 2028학년도 전형계획

학생 메뉴 **전형계획**(`/admissions-list`)에서 194개 대학명·218개 캠퍼스 항목을 검색하고 공식 시행계획을 엽니다. 대학 약칭 검색, 지역·요약 필터, 20건 페이지, 상세 직접 링크(`?plan=...`), PDF 항목별 쪽수 안내를 제공합니다. 한림대·춘천교대·한국교원대·포항공대 8개 전형에는 일부 요약과 근거 쪽수가 있습니다. 나머지는 원문을 제공합니다.

모든 항목은 검수 전 참고자료이며 성적·수능최저·지원자격 자동 판정에 사용하지 않습니다. 입학처 변경 공지와 최종 모집요강을 확인해야 합니다. HWP/HWPX/ZIP은 파일 형식을 표시하며 모음집 연결은 ZIP 내부 파일명을 안내합니다. 공식 원문은 제공처로 연결하고 전문 파일을 앱에 재배포하지 않습니다.

수집 범위·공식 출처·재현 방법: [전형계획 수집 기록](../work/_data/admission-plans/README.md). 공개 파일은 `public/data/admission-plans.json`이며, 프로젝트 루트에서 `python work/_data/admission-plans/build_catalog.py`로 저장된 수집 근거를 다시 묶습니다.
